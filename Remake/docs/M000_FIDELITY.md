## 修正的第一关偏差

早期导演补写把 m000 开场、胜利对白和第一次营救确认音误配给老赵，并按人物通用表把强子的当前武器切成步枪。真实 VWF 表明 m000 唯一可控队员是强子，且其 `default_attack_type = 4`。

当前实现已经统一为：

- m000 开场和胜利补写对白由强子发言；
- 首次营救彭鑫后从强子的 `acknowledge` 音频组选择确认音；
- 真实关卡实体存在时，以实体的 `default_attack_type` 作为当前武器；因此 m000 强子以匕首开始；
- 匕首、手枪和步枪仍作为本轮已采用的通用初始背包策略存在，玩家可自行切换；
- 程序化占位关卡或缺少合法原值时，才回退人物通用默认表。

补写文本和初始背包数量仍属于重制编辑；“强子、scene 1436、攻击类型 4”属于原数据恢复事实。

## 自动验收

2026-07-26 在 Godot 4.7.1、Compatibility renderer、GTX 1050 Ti、窗口模式下执行自动探针。探针不操作用户鼠标，完成了：

- 第一关真实资源加载；
- 可控角色移动和相机卷屏；
- 54 名敌军生成、43 条巡逻路线运行；
- 彭鑫与老罗叔两次营救；
- 队员和两名护送对象共同抵达 scene 1600；
- 胜利判定后重新加载第一关，验证任务事实和营救状态复位；
- 小地图、五列背包、暂停菜单和失败灰化菜单可见回归。

结果为 44 项运行检查全部通过，54 名敌军中 35 名在采样期内产生实际移动。360 帧样本的平均间隔为 16.708 ms，P95 为 17.400 ms，P99 为 17.982 ms；一次 59.013 ms 峰值发生在探针阶段切换。该早期短样本现已由十二关双轮 600 秒真实窗口门禁补充：m000 的 2,761 个稳态样本为 P95 17.495 ms、P99 20.823 ms、最大 24.517 ms、零个 >50 ms 帧。

数据文件包含 1,630 个实体；运行报告的 `entity_count = 1629` 是静态世界节点计数，因为唯一可控角色强子会从通用实体容器中抽出，再由队员系统单独生成，并不表示丢失实体。

## 画面证据策略

原版和复刻版探针都只处理游戏窗口，不截取完整桌面。原始帧只在内存中短暂存在；落盘前限制到最多 960 像素宽，并以 JPEG 质量 62 压缩。随后调用 Windows 本地简体中文 OCR 生成同名 `.ocr.txt`，分析默认读取 OCR 和 JSON 指标，不直接加载或上传原始窗口图。

本轮本地证据位于 `E:\1937\scratch\m000-fidelity-20260726`，属于可删除的测试产物，不提交 Git。五张压缩画面约 39—100 KiB，均生成了本地 OCR 文本。

## 后续扩展规则

第一关 baseline 是十二关模板。完成下一关对照时，应先把世界尺寸、实体/阵营、敌军武器与生命、巡逻、绘制队列、任务人物和锚点写入同一版本化目录，再运行真实资产回归和窗口探针。没有原版录像证据的对白、镜头和数值继续保留 `remake_editorial` 标签。
