# Remake 现代化体验稳定化实施与验收

日期：2026-08-06

范围：仅 `Remake`；不依赖 `Patch`/`Mod` 运行时代码，不生成或上传发行 ZIP。

## 1. 基线结论

上一轮《现代化改造实施与验收计划》的 46 项工程目标已经完成，证据见
[现代化改造验收报告](现代化改造验收报告.md)。本轮不是补做上一轮清单，而是把
试玩反馈中暴露出的移动、交互、AI 与 HUD 体验问题收敛为可复用的引擎能力。

## 2. 本轮完成内容

### 2.1 追击、动画与归队

- 敌人分别加载 `walk` 与 `run` 动作。进入 `CHASE` 时，有原版跑步序列的角色
  切换为跑步并使用与帧步幅一致的速度；缺少跑步序列的车辆/特殊角色只进行
  1.55 倍有限加速，不用走路动画伪装三倍跑速。
- 追击目标在 28 像素阈值内移动时复用现有路径；目标明显移动或路径失效时才
  重算，避免固定 0.5 秒无条件 A* 带来的卡顿和回退。
- 现代 AI 首次离岗时保存岗位坐标与巡逻游标。警戒/搜索结束后先进入
  `RETURN_TO_DUTY`，沿权威动态占用 A* 返回原巡逻路线，再恢复 `PATROL`；长距离
  正常行进不会被超时中断。该状态、目标、计时与游标均可存读档。

### 2.2 卡位恢复与导航请求治理

- 所有 `SquadUnit` 共用距离进展看门狗：每 0.35 秒采样路径游标和终点距离，
  连续 1.2 秒无有效进展才判定硬卡位。
- 硬卡位恢复只检查相邻八格，按静态净空、路径长度和 scene 奇偶确定绕行侧；
  仍使用 L3 与动态占用网格，不穿墙、不瞬移。失败后进入 0.75 秒冷却，避免
  重试风暴。
- 相邻格先用净空和目标距离廉价排序，只让前三名候选执行“逃离 + 续接”A*，
  单次恢复最多六次查询；角色看门狗再按 23 个确定性相位错峰，避免密集关卡中
  多名角色在同一物理帧集中寻路。
- 现代异步导航队列按 scene 合并尚未计算的旧命令。玩家快速连续点击时只计算
  最新目标，并在诊断数据中记录 `coalesced` 数量。

### 2.3 拾取与地面武器

- 新增确定性的拾取语义解析器，并为后续世界交互保留统一优先级目录。当前重叠
  拾取固定为松散双容器物品高于场景拾取物；点击处理再依次处理藏尸处、门、
  战斗目标与地面。显示层级不再决定拾取结果，显式 `B` 掩埋仍不会被物品抢走。
- 小型拾取物点击框向外扩展 12—14 像素，并以最近对象稳定决胜。尸体、藏尸处和
  掉落物同点时，无论尸体是否已掩埋，掉落物都优先进入拾取流程。
- 地面武器不再复用 50×50 的 PSD 工具栏按钮。物品 36—45 映射到原版透明世界
  精灵（包括 0372 步枪、0375 机枪、0377 手枪、0244 刀、0374 地雷等）；背包中
  仍保留原版工具栏图标。

### 2.4 Ctrl 强制攻击与声音诱敌

- 经典和现代操作都在选择/移动分支之前处理 Ctrl 强制攻击。
- 指向活物时沿用强制目标攻击；点击空地时，枪械在当前坐标方向播放原攻击动作、
  扣除弹药并创建真实投射物。枪声按武器警报半径传播，可隔墙被听见并诱导敌人
  调查；地雷、炸药和特殊控制不会被误当作空地射击。
- 近战只允许在原版等距攻击椭圆内空挥，不会隔空移动或伤害隐藏目标。

### 2.5 视线表现与判定一致性

- 绿色远区表示站立可见、卧倒隐藏；红色近区对站立和卧倒都可见。两区继续使用
  L2 超覆盖射线裁剪，墙体会真实遮挡。
- 巡逻视线以当前八方向朝向为中心做 ±18°、4.5 秒周期的自然摆动；搜索状态为
  ±34°、3.2 秒周期；追击/攻击直接朝向当前目标。
- 判定与空心扇形使用同一量化朝向。朝向按 3° 分桶，只有跨桶、跨导航格或缓存
  到期才重建 10 段轮廓，避免每帧执行大量视线查询。
- S 观察目标保持 8 秒；期间选择我方角色不会关闭扇形。目标死亡或计时结束才
  自动关闭。一次性观察埋点触发后仍立即删除且不写入存档。

### 2.6 HUD 安全区与可诊断性

- `GameShell` 公开底部 HUD 安全区；`MediaDirector` 根据 62 像素底栏动态上移
  字幕，工具栏不再遮挡对白。
- 开发诊断叠层和导出的诊断包增加活动路径、疑似卡位角色、成功/失败恢复次数、
  最差无进展时间与 scene；无需控制鼠标即可定位现场问题。

## 3. 可复用的工程方法

本轮沉淀了三个独立边界：

1. `WorldInteractionResolver` 只处理语义优先级和确定性决胜，不感知 UI 绘制顺序；
2. `MovementRecoveryPlanner` 只生成受 L3/L2 约束的有限绕行路线，不修改角色位置；
3. `NavigationRequestQueue` 只保留每个 actor 的最新未处理命令，并公开性能计数。

这三个组件均为无场景依赖的 typed GDScript，可用合成夹具单测；主场景只负责把
结果连接到玩法命令，因此后续新增关卡不需要逐关复制修复。

## 4. 自动验收

本轮新增或扩展的核心断言包括：

- 松散物品优先、扩大点击框与最近对象决胜；
- 空地强制射击、投射物与声音事件；
- 追击跑步/恢复走路以及 28 像素路径合并阈值；
- 红/绿视线姿态语义、巡逻摆头与追击朝向；
- 搜索结束归队、有限绕行不穿阻塞格；
- S 观察跨选择保持并按时消失；
- 62 像素 HUD 字幕安全区与 36—45 全武器世界素材映射；
- 同 actor 的过期异步 A* 请求合并。

2026-08-06 最终自动验收结果：

- Godot 核心逻辑 209 项、原版输入 101 项、世界引擎改进 54 项、现代化系统
  52 项、运行时轨迹 9 项全部通过；
- 真实视口输入 18 项通过，未调用全局鼠标移动、锁定或裁剪；第一关障碍路线与
  稳定 MOD 基线六个检查点差异为 0；
- `m009` 48 秒专项共 2,760 帧，P95 17.930 ms、P99 19.670 ms、最大
  39.889 ms、超过 50 ms 为 0；
- 十二关 1920×1080 窗口短门禁共 2,161 帧、69 项检查，P95 17.585 ms、
  P99 19.160 ms、最大 36.541 ms、超过 50 ms 为 0，且 207 个输入事件均只
  发送到目标视口；
- 1024×768 与 1920×1080 产品界面各 71 项通过，26 张规定截图通过尺寸、解码、
  亮度和唯一性检查；全部本地 JPG 已在本机 OCR，不上传原图；
- 产品界面探针会在进程内固定 1.0 原生像素缩放，再单独覆盖辅助功能缩放，既不
  受开发机持久化设置污染，也不改写玩家设置。

一次性 `Verify.ps1` 因宿主 30 分钟进程上限被终止在尾段；其前半段与后续原命令
序列已分段全部执行。分段之后又针对最后修改的恢复查询预算、输入、障碍路线、
十二关窗口性能和双分辨率产品 UI 重新执行门禁，以上数据均来自最终代码。

本轮没有生成绿色 ZIP，也没有上传发行物。`Build-Playable.ps1` 的 Godot 导出配置
使用 `all_resources`，只排除测试目录；两个新增运行时脚本均由正式脚本 `preload`，
因此用户以后主动运行既有打包脚本时会自动进入 PCK。转换资源仍由脚本复制到
`LocalAssets`，无需为本轮修改维护额外文件清单。

## 5. 非阻塞的外部体验验证

本轮推荐实施方案和可在当前开发机上自动验证的进一步现代化改进已经完成。以下
事项依赖真人体验或更多硬件，不属于代码未完成项：

- 用不同屏幕尺寸和 30/60/120 Hz 显示器采集追击、密集会车与字幕可读性体验；
- 逐关记录警戒次数、归队耗时、卡位恢复次数和失败原因，再调难度，而不是凭感觉
  改基础命中率；
- 增加手柄与键鼠无障碍预设、UI 导航朗读，以及学校机房低端核显矩阵；
- 用真人非作弊完整通关录像校准导演节拍和任务提示。自动脚本继续只做短路径和
  状态闭环，不尝试代替真人通关。
