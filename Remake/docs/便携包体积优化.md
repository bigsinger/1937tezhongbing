# Remake 便携包体积优化

## 结论

2026-08-06 使用 Godot 4.7.1 官方 Windows release 模板重新构建后，绿色包从
295.39 MiB 降到 159.64 MiB，减少 135.75 MiB（46.0%）。新包已经低于原版
约 200 MiB 的包体量级，并继续保持自包含：目标电脑不需要安装 Godot，也不需要
仓库、目录联接或开发机绝对路径。

| 指标 | 优化前 | 优化后 | 变化 |
|---|---:|---:|---:|
| `1937Remake-portable.zip` | 309,738,837 B（295.39 MiB） | 167,394,173 B（159.64 MiB） | -46.0% |
| `converted` 完整开发转换 | 329,979,275 B（314.69 MiB） | 163,355,048 B（155.79 MiB） | -50.5% |
| ZIP 解压后的完整自包含程序 | — | 276.13 MiB | 含 Godot 运行时 |
| Windows EXE | — | 104.02 MiB | 官方 Godot 运行时，保留 |
| PCK | — | 15.14 MiB | 游戏代码、数据与内置资源，保留 |

这里的“包体”是实际分发的 ZIP。解压目录仍大于 200 MiB，主要因为重制版包含
104.02 MiB 的完整 Godot 4 Windows 运行时；2001 年原版使用小型原生引擎，不能
直接拿其 EXE 与现代通用引擎逐字节比较。ZIP 中该 EXE 可压缩到约 36 MiB，因此
不会妨碍分发包低于 200 MiB。

## 原因分析

旧包大于 300 MB 的主要原因不是 CG，而是转换流程为了取证、调试和回退，同时
保留了多种等价表示：

- 2,775 张动作图集已经是运行时首选，但又附带 11,898 张独立动作帧；
- 980 张 `sprites/*.png` 预览图全部与各自 `group 0 / frame 0` 完全一致；
- 12 张完整地图使用 PNG，共 88,686,078 B（84.58 MiB）；
- 转换审计清单也被复制进了运行包，尽管运行时另有完整内容清单；
- Godot 官方 Windows EXE 是固定运行时成本，不能靠删除 CG 消除。

此前去掉 `logo.ogv` 和 `historical_intro.ogv` 只减少约 25.98 MiB，所以 ZIP
仍接近 300 MiB。

## 已实施方案

构建脚本现在只优化 `LocalBuild` 下刚复制出的发布副本，绝不修改
`Remake/LocalAssets` 中的完整开发资源。

### 1. 图集作为发布包唯一动作帧载体

删除发布副本中的 11,898 张 `fNNNN.png`。删除前，优化器会检查每一个
`sprite.json`、每一帧记录和每一组图集，确认 2,775 组图集完整覆盖全部帧。
运行时原本就优先读取图集；独立帧只是图集损坏时的开发回退。

### 2. 从图集重建精灵预览

删除 980 张 `sprites/*.png`。转换器生成预览的规则本来就是 SPR 的
`group 0 / frame 0`；优化器仍会实际解码全部 980 个预览和对应图集，并逐像素
比较 RGBA。任何一个不一致，构建立即失败，不会删除资源。

`ImportedSpriteAnimation.load_preview_texture()` 在完整开发资源中继续读取原预览；
在便携包中则返回图集首帧的 `AtlasTexture`。角色、门、物品、武器图标和特殊对象
共用这一安全回退，显示尺寸和像素不变。

### 3. 地图改为无损 WebP

12 张 `terrain.png` 转为 Godot 原生支持的无损 `terrain.webp`：

- PNG 合计：88,686,078 B（84.58 MiB）；
- WebP 合计：55,543,336 B（52.97 MiB）；
- 节省：31.61 MiB；
- 每张图编码后都会重新解码，并以 RGBA8 对全部像素逐一比较；
- `level.json` 同步改写为 `terrain.webp`，运行时也兼容开发目录的 PNG。

这里没有降低分辨率、颜色深度、透明度或纹理质量，也没有使用有损质量参数。

### 4. 去掉发布无关文件

Copy 包不再携带转换过程专用的 `asset-manifest.json` 和
`media-transcode-manifest.json`。运行包仍生成独立 `content-manifest.json`，记录
每个实际发布文件的长度、SHA-256 和整体内容身份。

导出预设同时排除 `tests/` 与 `tools/`；测试和发布优化器仍留在源码仓库，但不会
进入 PCK。

## 安全与回归门禁

本次验证结果：

- 合成资源优化测试：8 项通过；
- Godot 核心逻辑测试：209 项通过；
- 真实导入资源测试：26,127 项通过；
- 便携内容：4,207 个文件全部重新哈希并通过校验；
- 12 张地图全部通过编码前后逐像素比较；
- 980 张预览全部通过图集首帧逐像素比较；
- PCK 入口与最终 `1937Remake.exe` 均使用优化内容直接进入 `m000` 冒烟，无
  Godot/GDScript 错误；
- 生成 ZIP 后写入独立 `.sha256`。

以后执行 `tools/Build-Playable.cmd` 会自动重复这些检查。某个新资源没有图集、
预览不再等于首帧、WebP 往返像素不一致或复制内容校验失败时，构建会停止，不会
静默产出残缺包。`Junction` 模式不执行删除或转换，避免触碰开发资源。

## 暂不采用的进一步压缩

- 不对音频降采样或转有损格式，避免音质和时序变化；
- 不缩小地图、精灵、PSD 或 IBLOCK，避免画质与 UI 回归；
- 不使用 UPX 压缩 EXE，避免杀毒软件误报、启动开销和签名问题；
- 不维护裁剪模块的自编译 Godot 引擎。它可能继续减小解压体积，但会显著增加
  安全更新、导出模板和跨机器复现成本，而当前 ZIP 已达到低于 200 MiB 的目标。
