# 导航、动态占位、敌人感知与攻击

本文只把已经由资源、反汇编调用路径或真实关卡统计交叉验证的结论称为“原版参数”。复刻已经接入的行为和仍未完成的完整玩法分别列出，避免把几何核心误写成整套战斗已经完成。

## 1. 五张地图层各司其职

| 层 | 原版语义 | 复刻中的处理 |
|---:|---|---|
| L1 | 地块索引 | 高 16 位 tile-group ID、低 16 位 tile index，经 TLG 图集重建可见的 `terrain.png` |
| L2 | 视线/射击遮挡 | 普通敌人视线和所有已确认攻击的格线遮挡 |
| L3 | 移动障碍 | 玩家、敌人八方向 A* 和运行时动态占位的权威平面 |
| L4 | 事件设定 | 十二个正式关卡全为零，不据此虚构任务触发器 |
| L5 | 手动移动障碍修正 | 原样导出供研究；不与 L3 做运行时 OR |

L2 与 L3 不能合并：有些位置可看/可射但不能走，也可能能走却遮挡视线。把 L5 当作第二张碰撞层会制造原版不存在的封路和卡角。

可见对象的前后顺序不由 L1—L5 决定，而由 DBL `header[0]` 的绘制队列决定。导入链现在会把每个实体的 `database_header_values` 保留到 `ImportedLevelData`，并校验字段为数组且元素均为整数：m000 真实资源回归确认 22 个 DBL 336/337 庄稼底图处于 queue 1 固定背景，70 个 DBL 335 稻谷处于 queue 0 并与人物按 Y/基线排序。这样既不会让整块田地底片盖住人物，也保留独立稻秆的前后遮挡；移动命令不再绘制黄色目标连线。

L2/L3 已验证的值约定为：

```text
0                    开放
1                    静态障碍
scene_index + 1000   对应 SLIST 场景实体的占用
```

## 2. 静态地图与动态实体

`NavigationGridData` 永久保留导入的 L2/L3 快照，不在角色移动时改写源数组。`DynamicOccupancyGrid` 只接管明确注册为可移动的玩家和敌人；建筑、树木、车辆等未注册 scene 仍按源层阻挡，不能因为值大于 1000 就被全局放行。

动态占位遵守原版的所有权规则：

- 注册角色时以 VWF `ReferenceX/Y` 对应的源格为足印锚点，只取得包含该锚点的八连通分量；这避免把同一 scene 的历史/分离标记误合并成跨地图的巨型碰撞体，找不到足印才回退为单格；
- 寻路只忽略寻路者自己，其他角色、静态值 1 和未注册 scene 继续阻挡；
- 多格足印寻路会为每个候选锚点检查整副足印，不会只让锚点绕墙而让身体穿墙；
- 搬移先检查整段和全部新足印，任一冲突即整体失败；
- 提交时只移除 owner 等于自己的旧格，不会擦除墙或其他实体；
- 角色当前位置、L2 动态遮挡和终点预留一起更新，出生点不留“空气墙”；
- 4 像素密集采样防止大 `delta` 穿墙，12 像素角色间距、同帧移动边预留和对角交叉检查防止互穿；
- 玩家被阻挡持续 0.25 秒后按当前动态图重新寻路；敌人采用 0.65—1.00 秒的确定性错峰退避，避免拥挤处同时重算，不会退化为穿墙直线移动。

角色间距不再对整张角色表执行 O(n²) 扫描，而是按 32×16 原点格建立空间
owner 索引，只检查目标周围足以覆盖 12 像素间距的格。已经接受的同帧对角
移动也按 `from + to` 建立交换哈希，保持“先到者通过、反向穿越者拒绝”的
确定性语义。在 m004 这类超过 64 个动态占位格的地图中，A* 规划阶段以权威
静态 L3 和完整角色足印为基础，运行时迁移仍逐段执行动态碰撞、角色间距和
终点预留；这样不会因为瞬时人群把静态连通区域错误切成两半，也不会用性能
优化换取穿人或穿墙。

所有角色共享同一 overlay。m000 真实运行回归同时注册 1 名可控队员和 54 名敌人，巡逻过程中源 L2/L3 逐值不变。

十二关正式地图还执行完整静态足印审计：58,157 个匿名静态格和 58,955
个带 scene 编码的静态格在主运行时初始化后仍保持 solid；后者覆盖 6,710
个非活动角色 scene 足印。只有身份目录确认的 768 个活动角色、共 1,233
个源格会从静态 A* 释放并转交动态 owner。历史遗留或孤立的 scene 编码仍
按原 Layer 3 阻挡，不因“看起来没有对应角色”而猜测性删除。

七组已确认的门资源不再被当作永远静止的贴图。导入器按原 SPR
closed/open 锚点对齐两张逐像素 alpha 足印，只释放“关闭图有、打开图无”
且真实 VWF L2/L3 当前非零的格；因此不会把同 scene 或相邻建筑的障碍误删。
十二关共识别 96 个门实例，其中 94 个确实释放移动格，m010 两个实例只改变
外观而不改变源导航。开门只增量更新该 scene 的 L2/L3 释放 owner、AStar
solid、静态连通分量和受影响的多格足印净空，不再重建整张 A* 或清空无关
巡逻缓存；读档恢复关闭状态仍使用可安全分裂连通分量的完整重建路径。开门、
A*、L2 视线、存读档及十二关 96 个实例均有真实资源回归；仍待像素级校准的
是部分门与墙体前景的遮挡顺序，而不是开门导航生命周期。

## 3. 自动寻路与视线

`M37NAV1` 中间格式保留 L2—L5 的原始 `uint32`：

```text
char[8] magic = "M37NAV1\0"
uint32  version = 1
uint32  width, height, cell_width, cell_height
uint32  layer_count = 4
重复四次：uint32 layer_id（2、3、4、5）+ uint32 values[width*height]
```

Godot 以 `AStarGrid2D` 保存静态/动态 solidity，但可达路线不再使用现代
`AStarGrid2D.get_point_path()` 近似。IDA 已恢复原版 `sub_45F680`—
`sub_45FC10`：搜索从目标反向走向角色，正交格和对角格统一花费 1，启发值为
到角色起点的世界像素平方欧氏距离；邻居固定按西北、北、东北、东、东南、
南、西南、西展开。开放表按 `g+h` 升序，同分新节点插在旧节点之前；已在
开放表中的节点降分后不会重新排序。这些看似过时的细节会改变绕障碍路线和
停步朝向，因此作为兼容行为原样保留，而不是用单关特判修补。

动态占位仍对角色完整足印执行现代安全检查，并额外禁止同一物理帧两名角色
交叉对角换位。若临时角色/终点预约把一个静态连通通道切断，单格角色会保留
真实命令终点作为“延迟终点”；到达安全 partial path 边缘后，每个短移动
子步仍必须通过 L3、动态 owner 和间距检查，受阻即重新规划，因此延迟终点
不是可穿墙直线。两名同时有目标的角色相遇时，以 scene index 提供确定性
通行优先级，只在不同空闲格之间把 12 像素常规间距缩小到最低 4 像素；
静止角色、同格、墙体和静态断路仍是硬阻挡。双角色反向换位测试会逐帧推进
到两个原始终点，并拒绝重叠、死锁和把静态不可达目标错误续接。
目标在障碍中时会寻找附近可走格。十二关各选一名真实可控角色，提交一次
跨 L3 障碍命令和一次返回命令；共 72 个检查点逐一比较目标、位移和最终朝向，
稳定 MOD 与 Remake 的 `m000`—`m011` 结果均为零差异。m009 还固定了地图
边缘合法导航中心 `(16,1256)`，防止显示边距再次篡改原版目标。

检查点之外，MOD 探针和 Remake 探针都会在观察窗口内按每 5 个物理帧采样
实际位置。严格比较同时要求原版采样点贴合 Remake 规划折线、Remake 实际
采样点贴合原版轨迹、Remake 实际点贴合自己的规划折线；十二关均通过
4 像素门限，最差有向点到折线距离为 3.420 像素。这样最终位置相同但中途
绕错墙边的路线也不能再假通过。

角色移动从 SPR secondary 第 0/2 分量取得每个 60 Hz tick 的 X/Y 上限；
常见 walk/crawl 为 2/1 像素，run 为 6/3 像素。一个 tick 最多消费当前
路径点，不把余量带入下一段；精确到点则同 tick 推进游标，不额外停一帧。

十二关共有 516 条非空原始巡逻路线。稀疏地图继续按错开的原始 tick 读取
当时动态角色与目标预留，不在加载期冻结瞬时占位；超过动态障碍阈值、本就
按静态 L3 规划的密集地图，才在装载期按 scene 沿 A* 实际解析终点连续模拟
两轮巡逻。
普通往返直接命中精确缓存，角色因拥挤偏离一两个格后可从相同终点路线的
最近路径点复用后缀，密集图静态不可达的同一请求也复用空结果，避免按重试
周期重新扫描整张大地图。
多格角色的不可用锚点按足印形状预计算；关卡构造会先收集所有已载入动画中
运行时可达动作/方向的足印，待角色全部注册后统一完成一次预计算。每种足印
用与网格原点一一对应的 `PackedByteArray` 保存阻挡状态；构造单名角色和
首次切换动作不再扫描整张地图。开门只更新受影响候选格，并在可能新增通路时
清除旧失败缓存。不可达目标先通过静态连通分量重定向到起点一侧最近可达格，
防止 `m004`/`m007` 等大图退化为数百毫秒的全图 GDScript 搜索。

L2 采用 supercover 整数格线，沿途格和对角经过的两个侧格都会检查。普通敌人视线和手枪、步枪、机枪、投掷及近战攻击都受 L2 阻挡；观察者和目标可以忽略各自动态占位，但第三方动态实体仍会遮挡。

## 4. 原版敌人感知参数

DBL sprite header 的 h8（原记录 `+548`）是阵营：1 敌方、2 中立、3 友方；h12（`+564`）是特殊感知标记。十二关角色统计为敌方 656、中立 85、友方 31，另有 13 个 faction 0 角色类记录。特殊标记只出现在 DBL 1007 的军犬，正式关卡共 5 只。

普通敌人的感知区域是等距投影椭圆：横半径 640、纵半径 320 像素，二者都是 20 个 32×16 网格单元。角色方向值 1—8 对应北、东北、东、东南、南、西南、西、西北；MOD 的实测巡逻位移与自然接触指针共同验证了该顺序。原传感器先把屏幕像素按感知椭圆归一化，再使用如下逻辑角和瞬时半角：

```text
中心角：[270, 315, 0, 45, 90, 135, 180, 225]
半角：  [30, 45,  60,  45,  30,  45,  60, 45]
```

这些是归一化后的逻辑角，不能直接拿未缩放的屏幕像素做 `atan2`；32×16 等距投影会使最终屏幕扇形角宽随方向变化。原传感器以 3° 步进扫描逻辑扇区。感知椭圆分近、远两半：匍匐目标只在远半区规避普通识别，进入近半区仍会暴露。普通感知还必须通过 L2 视线。

`S` 观察时显示的红/绿区域只绘制边线，不填充实体。红色是远半区边界，
绿色是站立目标可见的近半区边界；两者按敌人当前 1—8 方向变化，并逐射线
被 L2 墙体截断。显示几何按敌人导航格、朝向缓存，并以 0.5 秒上限刷新移动
第三方遮挡；朝向改变立即重算。缓存只影响画线，权威 AI 感知仍在共同的
0.20 秒边界同步执行等距椭圆、方向、姿态与 L2 检查；这个边界已经由
m000 自然接敌差分固定，不能为均摊帧时而错开。尸体扫描只向守卫分发
尚未认领、尚未掩埋的真实敌军尸体，并保持世界插入顺序；角色死亡、认领、
掩埋和存档恢复都会重建该集合。这样避免密集关卡在没有尸体时执行
`敌人数 × 敌人数` 的空扫描，同时不改变原版“第一具合格尸体”语义。

军犬使用 320×160 像素、360° 的特殊感知路径，并绕过普通 L2 视线条件。代码只称它为“特殊感知”，不把未被程序证实的嗅觉解释写成事实。

## 6. 已接入的敌人行为

敌人已从静态预览升级为运行时角色，并与玩家共用动态占位：

- 读取阵营、出生方向、生命值、默认攻击和军犬特殊感知字段；
- 以 `reference_x/reference_y` 作为原版活动对象的实时出生位置；VWF
  `x/y` 在很多巡逻对象上是后续动作终点，不能再当作出生坐标；
- 把巡逻网格点换算为 `x*32+16, y*16+8`，按 L3 A* 循环巡逻；
- 跳过已经到达的连续巡逻点；整条路线退化为当前位置时进入低频等待，避免每个物理帧重复请求 A*；
- m000 差分恢复出 120/60 分量、134.164 px/s 对角巡逻位移和约 2.1 秒
  端点停留；
- 感知玩家后按 L2、方向扇区和近/远区进入追击；
- 进入对应武器椭圆且 L2 可达时进入攻击态；
- 丢失视线后先前往最后位置，再按原程序执行 5 个局部搜索点；每点相对
  当前坐标随机偏移 `x=±[0,31]`、`y=±[0,15]`，等待上限
  `rand()%160+40`，并在第五条路线完成后恢复巡逻；
- 攻击复核采用原版确认的 20—39 基础 tick 区间，并使用确定性的 scene 序列。

巡逻对象字段已经纠正：旧名 `Behavior` 实际是当前航点索引，旧名 `OriginX/Y` 实际是该索引所指航点的缓存世界坐标。十二关有 780 个巡逻对象，但只有 516 条非空路线；264 个空对象不能当作实际巡逻。`persistent_flag` 十二关全为 1，但其“启停”语义尚未证实，复刻只以路线是否非空决定能否巡逻。

m000 的只读 MOD 探针现已把 62 个动态阵营对象全部一对一追溯到 VWF。
早期保守留下的两组脚本四人编队通过“已解析前后邻居之间，同 runtime type、
runtime/VWF 两侧连续且等长”的约束恢复，没有使用位置近似或名称猜测。
巡逻基线审计第一关全部 54 名敌军；同一方法扩展到 m000—m011 后，共为
656 名敌军记录任务恢复运行后的四个检查点。Remake 严格比较所有身份和
两个一秒区间的逐角色位移、最大/P90 位移、移动数及静止数，十二关成对
复测均为零运动学差异。连续逐帧路线相位仍作为诊断输出，不把有限检查点
证据夸大成任意时刻逐帧等价。

玩家路线门禁已扩展为十二关：每关固定真实 scene、跨障碍目标、返回目标和
六个检查点。m001 特别覆盖“现代最短路向左绕、原版反向搜索向右绕”的分歧；
m009 覆盖最左侧导航中心。基线由隔离的稳定 MOD 运行时采集，输入只发送到
目标进程的 DirectInput，不移动系统光标或抢占前台窗口。日常验证会先检查
十二份基线身份和自洽性；本地存在转换资产时，再在 Remake 中逐关重放。

m000 的自然接敌差分让 scene 1436 玩家通过真实寻路进入 scene 1598
敌军的视野，不由测试代码直接设置 `current_target`。稳定 MOD 与 Remake
最终都必须保留同一目标身份、接敌态和未丢失态，接敌开始最多相差一个
离散检查点。这个回归同时固定了 1—8 的原始方向顺序，以及“先按 640×320
椭圆归一化、再计算逻辑角”的等距投影视线算法。它还逐检查点核对 54 名
巡逻敌军的当前/最大生命与默认攻击类型：强子生命精确为
`8,8,8,8,8,6,4`，两次伤害都来自 scene 1598，后者自身保持 8 点生命和
type 2 步枪。因此这条门禁覆盖实际命中与扣血，而不只覆盖接敌指针。
两个伤害检查点按有限物理帧截止期等待第 1、2 次真实命中后立即取样，
避免繁忙 CI 主机用墙钟计时提前截帧；敌人身份、每次 2 点伤害、命中顺序、
最终接敌态和截止失败仍为硬门禁。

三辆中立卡车（scene 1575—1577）和两只鸡（scene 1621—1622）现在也以
活动对象而非静态贴图存在。它们保留原始 DBL/VWF 身份、阵营、出生位置与

攻击态不再只是预览。玩家选择队员后左击敌人会自动追至有效射程；按住左 `Ctrl` 或 `↑` 再左击可强制目标/强制攻击。世界右键只用于拖框选择，不提交移动或攻击。敌人也会从巡逻、发现和警报状态进入同一套攻击执行器。当前战斗链路为：

1. 发起攻击前检查存活、阵营目标、武器椭圆射程和 L2 视线；
2. 对有限弹药武器扣除一次攻击所需弹药，再播放当前朝向的攻击动作；
3. **进入攻击动作最后一帧时**再次检查目标存活、射程和视线；类型 1—5 在此结算，类型 6/7/9 则在此生成世界投射物，等飞行命中或爆炸后才结算；
4. 原版 `sub_456DF0` 对直接 actor 目标的 attack type 1—7 都只调用一次
   伤害入口；机枪“三发”只属于坐标/非重合目标路径中的三条散布弹道，
   不能把一个角色目标重复扣血三次。飞镖/弹弓沿含首尾点的整数 Bresenham 路径分别以 16/5 像素逐 tick
   前进并按 L3 actor→L2 障碍顺序结算；手榴弹以 8 像素逐 tick 按原
   抛物线前进、飞行中忽略 L3/L2，并在终点下一 tick 创建 actor 61；
5. `sub_458700` 的非致命路径只执行免疫门与扣血，不写当前命令、攻击/装填动作或反馈计时；m000 连续受击仍执行返程命令也与此一致。致命伤才发出一次死亡事件，注销动态足印，播放一次死亡动作并停留在末帧；
6. 战斗信号把命中、爆炸/连锁爆炸、角色死亡、任务角色击毙和任务物品掉落交给主场景处理。

可供玩家使用的手枪、步枪、机枪、飞镖、弹弓和手榴弹均采用原版武器容器的
直接数量。mode 0 到零移除、mode 1 普通攻击耐久、mode 2 到零保留空枪；原版
没有弹匣、备弹或换弹。玩家各自持有 `CombatInventory`，从真实关卡拾取物获得

机枪、type 8 项目 43、手榴弹、type 10 项目 45），或用 `A`/`W` 打开
276×421 的右侧五列项目栏。敌人使用无限弹药，这是为了先形成可玩的战斗闭环，
不能解释成原版敌人确实拥有无限弹药。

### 6.2 type 8/10/11 专用路径的取证边界

以下高置信原程序路径已经成为当前专用运行时的约束：

- type 8 创建 actor 84，使用 GFL 470，并消费物品 43；该对象由存活的 faction 1 角色进入 32×16 椭圆触发；
- type 10 创建 actor 85，使用 GFL 900，并消费物品 45；对象在第 100 个 world tick 执行爆炸；
- type 8/10 都创建 actor 62；它在 128×64 等距椭圆内造成 128 主伤害并传播 800 半径警报，还会对两组特定 runtime actor type 结算附加 128 伤害；效果 11/15 使用原 MSVCRT 序列尝试 1—2 个 64×32 散布粒子，每个成功粒子播放 5 轮；
- type 11 不走直接伤害结算，物品 99 不消费；目标 `+656/+0x290` 是注意力保持标志，暂停普通空闲移动并面向专用来源，来源开始移动或目标进入战斗转换时清除。

当前 `LegacySpecialWorldObject` 覆盖 type 8/10 的部署、激活、触发/计时、爆炸、结束和清理；`LegacyAiControlEffect` 覆盖 type 11 的应用、重复刷新、来源锚点、来源移动/战斗转换/死亡/切关释放。活跃生命周期进入存读档，旧存档中的合成超时字段仅作兼容读取，不再影响状态寿命。

m011 不再编辑性发放项目 99。项目 99 已确认由古明在军服 54 的第 101 个
角色 tick 换装完成时自动取得；青衫 92 逆向换装时移除。type 11 因此已经
进入第一关真实物品/角色流程，不再只存在于独立测试。

因此 type 8/10 需要具有所有者、阵营、触发/计时和销毁状态的持久世界对象，type 11 需要保存来源锚点且可按原条件解除的 AI 状态，而不是复用一次性命中。actor 62 的粒子集合、首匹配资源、散布和寿命已经确认；尚未完全对齐的是其他系统对同一个全局 `rand()` 的调用顺序，因此任意实机时刻的具体随机变体仍可能不同。

原伤害函数已证明不存在非致命反馈动作或硬直写入，当前实现只扣生命并保持
动作/命令；死亡动作和最后一帧保持已经接入，没有死亡动作资源时会保留当前
图像并仍然正确进入死亡状态。

### 6.3 警报传播

- `sub_45DDA0` 的普通警戒参数为 640。它不是圆形，也不是把目标指针分享
  给友军：`sub_45A7C0` 在接收者方向构造
  `(640*cos(a), 320*sin(a))`，再用严格 `<` 比较欧氏距离；
- 接收者必须是存活 faction 1、runtime type 不为 91，且没有“未丢失的
  活目标”。玩家阵营声源写声源坐标；敌军声源若已有目标则写该目标当时
  坐标。命令不会获得可隔墙持续追踪的 live target；
- 声音是事件驱动的，静默玩家即使位于范围内也不会产生持续全向警报；
  传播不检查 L2，亦即原版普通声音无视墙体。明确制造声音走同一坐标调查；
- 原攻击分发中手枪、步枪、机枪存在 640 调用点，但稳定 MOD 的 m000
  实测还证明 scene 1598 两次步枪攻击时，相邻的持久巡逻 scene 1433
  保持原路线。该“警戒命令与持久巡逻脚本的仲裁”尚未完全反编译；原版
  模式保留这条实测结果，不把普通敌军射击强制升级为全队追击。编辑难度
  仍可通过明确标注的协作队列增强；
- faction 1 死亡由 `sub_4585F0` 发出 256 坐标脉冲；type 8/10 的 actor 62
  爆炸由 `sub_4554A0` 发出 800 脉冲。两者都仍是坐标命令，不直接赋予
  击杀者/玩家目标指针；
- 丢弃物品不走听觉广播。它按 runtime type 白名单、当前朝向近区、L2
  视线和世界插入顺序进入独立取物生命周期；
- 敌军还会在当前朝向的外视野带发现第一个未认领、未掩埋的 faction 1
  尸体，并要求 L2 可见。尸体被原子认领后，观察者接近、等待
  `rand()%40+40` 且严格超过上限，再进入上述五点搜索；同时在最近
  runtime type 93 标记处生成两名 type 6 增援并置全局警报。尸体认领、
  警报、动态增援身份和搜索状态均进入存档；
- 未营救护送角色保持 faction 2 中立；营救后切换 faction 3，才进入正常
  敌对关系。
