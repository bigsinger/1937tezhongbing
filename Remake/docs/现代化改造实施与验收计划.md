# Remake 现代化改造实施与验收计划

## 1. 目标与边界

本计划只针对 `Remake` 子项目，不以 `Patch` 或 `Mod` 的实现方式作为设计前提。目标是在保留十二关可玩闭环和经典玩法的同时，把当前工程推进为可维护、可扩展、可分发、可在现代 Windows 设备上稳定运行的产品。

阶段性完成不等于目标完成。只有第 7 节的全部验收项通过、正式构建能够独立运行、文档与测试同步更新后，整体目标才算完成。

## 2. 基线结论

### 2.1 已有优势

- 十二关地图、角色、任务、战斗、物品、存档和媒体流程已经形成可运行闭环。
- 已有较强的自动化基础，包括格式测试、脚本解析、确定性状态、真实资源、十二关输入旅程和性能探针。
- 现有自定义导航包含静态网格、动态占用和路径缓存，不需要为了“现代化”而盲目替换。
- 基准机器在 1920×1080、GTX 1050 Ti 上能够基本维持 60 FPS。

### 2.2 主要风险

- `main.gd`、`squad_unit.gd`、`enemy_unit.gd` 和 `game_shell.gd` 体积过大，系统职责交叉，继续直接追加功能容易产生全局回归。
- 首次打开武器栏、物品栏以及集中寻路请求仍会产生约 40～50 ms 的瞬时卡顿。
- 资源由大量外部 PNG/JSON/WAV 文件组成，加载和分发链路不够自包含。
- 当前性能基准受 60 FPS 限制，能反映视觉帧间隔，但不能准确反映 CPU、物理和渲染余量。
- 显示设置、存档即时状态、现代操作、无障碍、本地化、AI 可读性和教育内容尚未形成完整产品体验。

## 3. 总体架构目标

```text
Application / Composition Root
├─ SimulationCore
│  ├─ Commands and Events
│  ├─ Combat
│  ├─ Perception
│  └─ Mission
├─ WorldServices
│  ├─ Navigation
│  ├─ SpatialIndex
│  ├─ Occupancy
│  └─ Audio
├─ Presentation
│  ├─ Renderer
│  ├─ Camera
│  ├─ HUD
│  └─ Menus
└─ Persistence
   ├─ SaveGame
   ├─ Checkpoints
   └─ Diagnostics
```

采用渐进式抽离，不进行一次性推倒重写。`main.gd` 最终只保留启动、依赖装配、场景切换和高层事件路由。

## 4. 分阶段实施内容

### 阶段 A：稳定性、性能基准与发行

- [x] 建立不锁帧性能采样，同时记录帧时间、物理时间、导航查询、绘制调用、对象数、内存和加载阶段。
- [x] 建立首次打开武器栏、物品栏、视线和姿态切换的延迟门禁。
- [x] 预热常用图标、字体、窗口和音效，消除首次操作尖峰。
- [x] 为导航请求增加单帧预算和延后队列，避免输入引发查询风暴。
- [x] 补齐桌面/自定义分辨率、VSync、帧率上限、无边框、UI 缩放和失焦暂停设置。
- [x] 验证 100%/125%/150%/200% DPI、16:10、16:9、21:9、4K 和多显示器边界。
- [x] 建立版本化内容清单和资源完整性检查。
- [x] 提供自包含便携构建；运行时不依赖开发机绝对路径或 Junction。
- [x] 使用正式 Godot 导出模板，生成发布包、校验文件和构建元数据。

### 阶段 B：架构与运行性能

- [x] 建立统一的命令、事件和运行服务接口。
- [x] 将设置应用、检查点、诊断、感知调度和空间查询从 `main.gd` 抽离。
- [x] 建立动态空间索引，服务于敌人、角色、尸体、掉落物、门和投射物查询。
- [x] 将敌人感知错峰调度，避免所有敌人在同一帧扫描。
- [x] 投射物和爆炸只查询相关空间单元，不再复制、排序全部战斗对象。
- [x] 小地图采用增量标记更新，避免固定周期完整重建。
- [x] 多人巡逻共享主路径/走廊，并保留局部避让和队形间距。
- [x] 为同步关卡载入加入可见进度；数据解码与文件读取可后台执行，节点创建留在主线程。
- [x] 为核心系统建立类型化数据边界，减少热路径的动态字典和反射调用。

### 阶段 C：现代操作、UI、存档和辅助功能

- [x] 保留经典操作方案，并提供现代 RTS 操作预设。
- [x] 支持控制组、相机书签、双击选择同类单位和可配置镜头参数。
- [x] 明确显示不可达、距离不足、弹药不足、遮挡和命中失败原因。
- [x] 攻击预览显示武器、射程、命中率和声音影响范围。
- [x] UI 支持缩放、字体缩放、安全边距、键盘导航和高 DPI。
- [x] 红绿视线区域增加纹理/边线差异，不只依赖颜色。
- [x] 完整字幕覆盖对白及关键环境声音。
- [x] 提供高对比度、大光标、减少闪光、减少镜头运动和可选失焦暂停。
- [x] 建立本地化目录与 `tr()` 文本入口，新增文本不再直接写死。
- [x] 增加关卡开始、关键目标完成时的滚动检查点自动存档。
- [x] 明确即时动作的保存语义；安全帧保存或完整恢复进行中动作。
- [x] 增加存档版本迁移、损坏检测和回退。

### 阶段 D：玩法、AI 与教育内容

- [x] 将“规则集（经典/现代）”与“难度（剧情/普通/困难/自定义）”分离。
- [x] 现代难度综合调整反应时间、感知、搜索、警报、增援和资源，而不是只改变命中率。
- [x] 玩家攻击随机结果具有可见的命中率和失败原因反馈。
- [x] AI 增加怀疑值、记忆衰减、最后已知位置和合理搜索区域。
- [x] AI 小队支持队长、跟随、警戒、包抄等角色及有距离和延迟的警报传播。
- [x] 提供感知、声音、路径和 AI 状态开发调试视图。
- [x] 十二关提供历史背景、目标语境和通关后“史实与艺术加工”说明。
- [x] 增加人物、地点、武器与历史事件词条，以及可选挑战和复盘统计。
- [x] 对适龄提示、暴力内容和教育模式提供独立开关与说明。

### 阶段 E：质量、诊断与发布

- [x] 增加低端核显、GTX 1050 Ti、Win10、Win11、1080p、4K 的性能矩阵。
- [x] 增加 30～60 分钟稳定性测试、反复换关和存读档内存增长测试。
- [x] 增加焦点切换、显示模式切换、设备热插拔和异常资源包测试。
- [x] 增加 UI 多分辨率截图回归和基础可访问性检查。
- [x] 生成玩家可导出的诊断包，包含版本、设置、最近命令、关键日志和可复现种子，不包含存档隐私内容。
- [x] CI 构建正式发布产物，并生成 SHA-256 校验文件。
- [x] README、开发文档、运行帮助和发布说明与最终行为一致。

## 5. 性能验收预算

以参考机器和低端核显分别建立基线，发布门禁采用以下目标：

| 指标 | 参考机器目标 | 低端核显目标 |
|---|---:|---:|
| 1080p P95 帧时间 | ≤ 18.5 ms | ≤ 25 ms |
| 1080p P99 帧时间 | ≤ 25 ms | ≤ 33.3 ms |
| 单次首次 UI 操作尖峰 | ≤ 25 ms | ≤ 40 ms |
| 正常关卡切换 | ≤ 3.5 s | ≤ 6 s |
| 第二轮十二关内存净增长 | ≤ 8 MiB | ≤ 8 MiB |
| 30 分钟运行崩溃/脚本错误 | 0 | 0 |

若硬件环境无法覆盖低端核显，CI 仍执行结构门禁和软件渲染冒烟，本地报告明确标记“未验证”，不得伪报通过。

## 6. 兼容策略

- 经典规则和经典操作作为兼容预设保留。
- 现代规则、现代操作和辅助功能使用同一模拟核心，通过配置策略切换。
- 存档包含规则集、难度、版本和内容清单身份，禁止在不提示的情况下改变旧存档语义。
- 架构抽离期间，每一步都需要通过现有十二关确定性和真实输入回归，不能以重构为理由破坏已有功能。

## 7. 整体完成定义

只有同时满足以下条件，目标才算完成：

1. 阶段 A～E 的所有复选项完成，或对不适用项给出可审计证据和替代验收。
2. `Verify.ps1` 的无资源测试、真实资源测试和场景冒烟全部通过。
3. 十二关输入旅程、任务成功/失败、存读档、门、物品、战斗和导航回归通过。
4. 正式便携构建可从不包含源码和开发工具的独立目录启动。
5. 自包含构建不依赖 `LocalAssets` 的绝对路径、Junction 或开发机安装状态。
6. 性能报告达到第 5 节预算；无法覆盖的硬件项目明确列入发布说明。
7. Git 工作树中不包含运行产生的存档、日志、临时截图或机器专用配置。
8. 文档、自动化测试和最终构建对应同一提交。
