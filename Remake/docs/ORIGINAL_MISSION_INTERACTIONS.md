# 原版关卡专用交互与任务求值恢复

## 1. 证据边界

本页记录稳定 MOD 中 `sub_404BB0`（任务指针初始化，RVA `0x4BB0`）和
`sub_405410`（任务求值，RVA `0x5410`）可以直接证明、但不能用通用
`E` 键热点替代的关卡规则。分析输入是仓库稳定 MOD 的 `M1937.exe` 与十二张
原 VWF；本地 IDA 数据库只用于生成反汇编证据，不随发布包分发。

原函数按运行时类型扫描同一 actor 数组：type 98 是“检测爆炸精灵”，
type 100 是出口，type 85 是物品 45 部署出的定时炸药。`sub_45EF90`
按运行时类型找第一个对象，并用 `sub_45A040` 的欧氏距离执行严格 `< radius`
比较；它不检查对象生命，所以已经触发但仍留在原 actor 数组中的 type 85
同样满足任务查询。

## 2. 已恢复的六关规则

| 关卡 / 原分支 | 爆破或任务物品判定 | 出口判定 |
|---|---|---|
| m001 / case 2 | 两个 type 98 的生命必须 `<= 0` | 古明当下必须为伪装 type 91；古明和 type 19 司机分别距最后 type 100 `<= 128` |
| m002 / case 3 | 一个 type 98 的生命必须 `<= 0` | 老赵与获救强子分别距 type 100 严格 `< 128` |
| m003 / case 4 | 五个 type 98 各自严格 128 内存在 type 85 | 老赵、强子、古明、大牛分别距 type 100 `<= 128` |
| m004 / case 5 | 两个 type 98 的生命必须 `<= 0`；物品 101 必须在古明或大牛的 `+0x228` 容器 | 无出口条件 |
| m006 / case 7 | type 15、type 22 均死亡，且物品 101 必须在强子的 `+0x228` 容器 | 稳定 MOD 分支没有接头点或出口条件 |
| m008 / case 9 | 四个 type 98 各自严格 128 内存在 type 85 | 老赵与大牛分别距最后 type 100 严格 `< 128`；没有额外手动引爆条件 |

m001 的“取得军服”仍作为玩家可读的前置目标，但出口会再次检查古明的实时
类型；穿上后又脱下不能利用已经完成的目标状态进入火车。m004 的计划书可以被
其他角色实际拾取和携带，但只有转交给古明或大牛后才推进原任务条件。

## 3. Remake 接线

`game/scripts/legacy_mission_rules.gd` 是运行时单一规则表，SDK 的
`include/M1937SDK/Mission.hpp` 保存同一组类型、半径、边界、角色位掩码和
物品持有人约束。

- m001/m002/m004 不再允许对爆破标记按 `E` 直接完成。真实世界爆炸只有在
  `128 × 64` 爆炸椭圆覆盖绑定的 type 98 时才发布目标事件。
- m003/m008 在 actor 85 真正生成时执行原 `sub_45EF90` 严格半径查询；物品
  已在攻击命中帧由角色容器消费，不会在任务层重复扣除。
- 出口检查复用同一个目标视口/世界坐标流程，但逐关应用严格或包含边界，并在
  m001 额外核对古明的实时运行类型。
- m004/m006 不把一次拾取事件永久冒充容器事实；运行时按原 evaluator 周期
  检查物品 101 当前所在的角色背包。错误持有人不会推进，丢下后再交给合格
  队员可以正常继续，旧存档中已经持有的物品也会被重新识别。
- `activated_mission_scenes` 继续作为已经成立的原 actor 条件快照进入存档；
  读取时不会要求玩家再次制造已经完成的爆炸。

非上述六关仍使用各自已经恢复的任务路径；没有证据的关卡不会自动获得这些
专用规则。早期通用 `charge_policy` 保留给合成 fixture 和没有原任务规则的
兼容内容，不再覆盖这六个稳定 MOD 分支。

## 4. 自动证据

- `legacy_mission_rules_test.gd` 固定六个分支、type 98/85/100、严格与包含的
  128 边界、`128 × 64` 爆炸椭圆及 m004/m006 物品持有人。
- `real_mission_world_loop_test.gd` 在真实 m001/m002/m003/m004/m006/m008
  关卡中先证明 `E` 不能伪造爆破，再生成真实 actor 85；需要摧毁 type 98 的
  分支推进到第 100 world tick 触发 actor 62，邻近查询分支在 actor 85 出现时
  立即求值。每个稳定目标完成点仍执行物理磁盘存读和状态哈希校验。
- `director_main_wiring_test.gd` 证明原世界条件在发布同步镜头事件前先进入活动
  scene 集合，事件被拒绝时会回滚。
- `combat_mission_runtime_test.gd` 固定物品 101 的当前容器语义：老赵持有时
  m004 不推进，转入古明背包后才完成计划书目标。
- SDK 原生测试固定六项表和边界公式；这轮增加后为 1,526 项可执行检查。

这些是数十秒到一分钟级的单行为门禁，不是自动通关机器人。十二关非作弊真人完整通关仍是
发布验收项，不能用上述局部闭环冒充。
