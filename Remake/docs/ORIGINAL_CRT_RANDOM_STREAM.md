# 原版全局随机流恢复

## 目标

原版没有为角色、AI、爆炸等系统分别创建随机数生成器。受支持的
`M1937.exe` 直接调用 MSVCRT `rand()`，且程序没有调用 `srand()`；所有系统
因此共享从状态 `1` 开始的一条进程级 LCG：

```text
state = state * 214013 + 2531011 (mod 2^32)
value = (state >> 16) & 0x7fff
```

只复现公式还不够。要逐次一致，还必须恢复每关加载阶段消耗了多少次、角色按
什么顺序更新，以及运行期每个调用点何时消费。本文记录可重复的取证和当前接线
边界，避免把“确定性”误称为“已经与原版逐次一致”。

## 安全的原版取证

`Patch/src/dinput-proxy/dinput_proxy.cpp` 提供显式环境变量
`M1937_RNG_TRACE=1` 才启用的测试钩子。它只修改本次启动的游戏进程：

- 在 `crt_rand` 入口记录返回值、调用点 RVA、线程和调用者保存的 ESI；
- 热路径只写入固定容量内存环，不执行磁盘 I/O；
- 低优先级后台遥测线程批量写 JSONL；
- 不移动、锁定、裁剪或读取桌面全局鼠标；
- 正常玩家启动时环境变量不存在，钩子完全不安装。

启动阶段探针使用 `--crt-random-startup-only`。角色表就绪后，它只等待一个
很短的目标进程本地时间窗，保存角色地址/索引快照并退出，不发送全局输入。

典型取证流程：

```powershell
$env:M1937_RNG_TRACE = '1'
.\Patch\analysis\tools\Test-ModRegression.ps1 `
  -Levels 0 `
  -CrtRandomStartupOnly `
  -OutputRoot E:\1937\rng-capture

.\Remake\tools\Summarize-CrtRandomTrace.ps1 `
  -TelemetryPath E:\1937\rng-capture\level-01\crt-random-telemetry.jsonl `
  -ActorStatePath E:\1937\rng-capture\level-01\actor-states-crt-startup.csv `
  -LevelId m000
```

`Summarize-CrtRandomTrace.ps1` 会拒绝序号断裂、LCG 值不连续、SDK 未登记调用点
或无法映射的观察门角色。十二关摘要再由
`Build-CrtRandomStartupBaseline.ps1` 合并为运行时目录。

持续运行取证仍使用同一个仅进程内钩子，但每条记录额外保存
`GetTickCount()` 毫秒时间戳。生成器
`Build-CrtRandomRuntimeTimingBaseline.ps1` 会重新验证完整 LCG、调用点目录、
角色地址映射、逐轮角色顺序和节拍稳定性；固化结果由
`Test-CrtRandomRuntimeTimingBaseline.ps1` 纳入每次 `Verify.ps1`。

十二关约五秒的角色运行态、路线/静止共用计数器、持久追击关系、五点搜索、
环境粒子和压缩寻路优化的完整证据、命令及边界见
[原版全局随机运行态基线](CRT_RUNTIME_STATE_BASELINE.md)。

## m000 连续运行节拍基线

`game/data/original_crt_random_runtime_timing.json` 保存了进入第一关游戏场景后
连续 710 个角色更新轮次的进程内实测。证据范围只用于角色调度，不采纳该次
自动化中未成功送达的地面移动结果。原始序列共 51,246 次调用，序号连续、
每个返回值均重新通过 MSVCRT LCG 校验，且所有调用点都在 SDK 目录中。

- 每轮严格按原 runtime 顺序调用 54 名角色的 `0x0005C81C` 观察门；
- 每轮随后由 runtime actor 125、126 各调用一次 `0x00055216` 主候选扫描；
- 710 轮共得到 38,340 次观察门和 1,420 次主候选扫描；
- 去除一个同毫秒采样和一个大于 40 ms 的停顿后，707 个稳态间隔平均
  16.685997 ms，即 59.930491 Hz；中位数 16 ms，P95/最大值 31 ms；
- 基线同时固定逐调用点计数、观察门角色顺序和跨轮角色调用顺序哈希。

因此观察门与主候选扫描属于原版约 60 Hz 的 actor update，而不是 30 Hz
待机/反应计数器。Remake 将两类消费者放在同一 60 Hz 角色调度中，并把各自
相位、最新结果和序号写入局内存档。后续关卡仍须分别取得长时证据，不能仅凭
m000 推断所有条件分支。

m004/m005/m006 的独立约五秒运行态证据进一步覆盖正式次级搜索。三关分别有
9/9/7 名实际进入 `sub_45CE90` 的角色：其中 9/8/5 名由 `sub_454960`
直接分发为 type 16/20/25/27/28/29，m005 的 type 18 孙小姐及 m006 的
type 18 孙小姐/type 26 铁蛋娘则由 `sub_4550A0/sub_454D90` 回落；
`0x5CEA6` 门调用数为 1010/1028/1255，四联目标偏移触发数为
16/30/21。反编译与原始序列共同固定：contact 为 0 才取门值，活动路径期间
不取值，路径完成的第一轮只清 contact，下一轮才恢复门控。Remake 已按
runtime-index 物理优先级执行这条循环并保存完整相位。

## 十二关连续轮次基线

`game/data/original_crt_random_recurring_timing.json` 把已有的十二关短时进程证据
重新按“下一轮首名观察门已经出现”划分为可证明完整的 actor update。每关最后
一个没有后继边界的尾轮会主动丢弃，不用截断数据猜测完整帧。当前机器可读基线
合计固定：

- 5,845 个完整 60 Hz 更新轮、571,275 次连续 `rand()` 调用；
- 343,445 次可映射到 runtime actor 的调用；
- 每关起止序号、最终 LCG state、逐调用点计数、逐 runtime actor × 调用点计数
  及其独立 SHA-256，并保留原始证据 SHA-256；
- 每一轮以及整段的“调用点 + runtime index”和“调用点 + runtime index + 值”
  SHA-256；非角色调用统一编码为 `runtime_index = -1`；
- m000—m011 各自 187—567 个完整轮次，最短证据仍超过 3.5 秒。

`Build-CrtRandomRecurringTimingBaseline.ps1` 会流式重算完整 LCG、验证 SDK 调用点
目录、角色地址映射和每轮观察门顺序；`Test-CrtRandomRecurringTimingBaseline.ps1`
不读取原游戏文件，固定十二关摘要并逐轮检查序号连续性、计数、首轮哈希、首轮
最终 state，以及每关全部“角色 × 调用点”计数的排序、合计与独立哈希，已经进入
`Verify.ps1`。

同一生成过程还会把五个 `sub_45D060` 调用严格按组校验并写入
`original_crt_random_local_search_timing.json`。较长的连续轮次证据共包含 107 组，
每组都固定 round、runtime actor、调用点顺序、返回值及调用前的位置、共享计数、
路径和路线状态；任何缺项、跨角色或顺序错位都会使生成/验证失败。

生成器还会输出
`game/data/original_crt_random_actor_event_timing.json`，把条件调用压缩为逐
actor/round 事件表。schema 2 现在覆盖全部 20 个已见条件调用点，十二关共固定
29,662 条事件：主搜索门 `0x55216` 7,143 次及四联偏移 44 次，阻塞重试四联
偏移 172 次，共享静止/路径/路线计数分别为 1,464/11/1,024 次，跟踪目标反应
`0x5CB2B` 1 次，次级搜索门 `0x5CEA6` 4,776 次及四联偏移 336 次，追击重采样
`0x5D47E` 14,691 次；这段证据中 `0x5D394` 为 0 次。每条带快照的记录保留位置、
前一位置、共享 counter/limit、路线/路径状态、目标、命令变体和追击 runtime
identity；钩子没有附快照的调用点只保存能证明的轮次、角色、调用点和值，绝不
补造字段。`Test-CrtRandomActorEventTimingBaseline.ps1` 会逐关固定条数与
SHA-256，并与完整轮次基线逐调用点交叉核对，同时拒绝残缺的门控/四联偏移组。

Remake 的 parity 跟踪只有显式设置 `M1937_REMAKE_RNG_PARITY_TRACE=1` 或命令行
`--trace-legacy-rng-parity` 才启用。普通游玩继续对环境粒子批次作 O(1) 提交，
没有逐调用哈希开销。无界面诊断脚本
`tests/recurring_crt_random_parity_probe.gd` 可让十二关各运行到基线轮数，比较四组
全局哈希、逐调用点计数和逐角色调用点计数；任一差异会直接报告
`runtime_index:call_site=actual/expected`。全程不打开原版、不发送键鼠消息，也不
尝试通关。

十二关无界面批量诊断已经把首轮以后的差异逐关、逐角色定位并闭合到路线/静止
共用计数、主搜索、阻塞重试、跟踪反应、次级搜索、追击路径状态和五点搜索。
在这 5,845 个无输入完整轮次内，十二关现均通过调用总数、调用点/actor 顺序、
返回值及最终 LCG state 的 16 项逐关校验。该结论严格限于已记录的无输入证据
窗口；它不是玩家操作后长期运行期已经全局逐调用相等的声明，也不需要打开
第一关或尝试人工通关。

现有进程私有记录还包含一个严格受限的 `m000-basic-movement-v1` 输入分支：
玩家运行时 actor 18 被选中后先移动到 `(48,56)`，再返回 `(176,56)`。离线生成器
`Build-CrtRandomInputBranchTimingBaseline.ps1` 从原记录恢复 413 个完整轮次、
24,586 次调用和 2,281 条条件 actor 调用；前 297 轮与无输入目录逐轮完全一致，
第 298/358 轮分别在 actor 18 的更新槽消费 `0x5D7CF`。因此接令语音已从鼠标
处理函数中的同步调用改为角色更新槽队列。`input_crt_random_parity_probe.gd`
只提交这两个已记录地面命令，现已逐调用匹配调用点、actor、返回值和最终
`0xE9B3096A` 状态，同时验证角色完成往返路线。该探针无界面、不控制系统鼠标、
不与敌人交战，也不尝试完成第一关。

## 当前运行时接线

机器可读覆盖表位于
`game/data/original_crt_random_runtime_coverage.json`，并由
`tools/Test-CrtRandomRuntimeCoverage.ps1` 在 `Verify.ps1` 中对照 SDK 目录逐项
校验。当前 32 个调用者、119 个直接调用点均有且只有一条分类记录。IDA 入站
代码/数据引用、PE 入口与十二关进程内轨迹证明 `0x0005BFAC` 属于无调用者的
角色重载 API，`0x00061DFC/0x00061E3A` 属于无调用者的地图填充/自动拼接 API；
正式关卡因此有 107 个可达调用点，其中 106 个已有实时消费者，1 个载入音乐
调用由精确首轮检查点恢复，缺失数为 0；其余 12 个调用点只属于无效关卡调试、
无引用函数或地图创作 API。完整证据见
[`SDK/docs/NativeCrtRandomReachability.md`](../../SDK/docs/NativeCrtRandomReachability.md)。
两个角色析构重置调用者已覆盖顾明换装、actor 84/85 部署物、actor 90 观察
标记、actor 78 藏尸替换、手动掉落物、actor 57/80/81 飞行视觉、actor 60
命中特效，以及 actor 61/62 主体、火焰与碎片退役路径；m006 任务 actor 101
的建立、存档恢复、type 22 取走与析构也已接线。其余尚未分类的原生管理器
删除生命周期仍明确标为 `partial`。覆盖表
不会因为调用点常量出现在生成目录里就把它误判为已实现。

已接入同一可存档/回放流的部分包括：

- 十二关初始化后的首个完整更新轮次、actor 绑定观察门结果和 76 份更新后
  状态；路线等待、次级搜索、阻塞重试与追击导航按证据应用；
- 在完整无输入证据窗口内，若某角色的原版入口/出口快照均无目标、无 contact，
  且当前轮没有 `0x5CCCD/0x5CD01` 跟踪目标事件，则禁止由稀疏巡逻样本的 A* 插值
  凭空建立新接触。这只约束已证明的短窗口；首次未收录玩家输入或证据耗尽后，
  实时视线、听觉与攻击检测立即恢复；
- m000 连续 710 轮证明的 60 Hz 观察门与主候选扫描节拍、actor 顺序和存档
  相位；
- 十二关 5,845 个完整更新轮的版本化原版调用点/角色/返回值哈希，以及仅在
  诊断模式启用、普通游玩零逐调用开销的 Remake parity 哈希器；
- 十二关 29,662 条、20 个调用点的主/次搜索、阻塞重试、跟踪反应、共享计数、
  路线等待与追击条件事件，以及 107 组连续轮次五点搜索；
  默认只在关卡启动后、尚未收到任何玩家按键或左右键点击的短暂证据通道中按
  runtime actor/round 消费；唯一例外是测试显式选择上述版本化移动分支，此时
  使用该分支自身 413 轮事件表。普通游玩中的首次未收录输入、证据轮次用尽或
  读取已退出的存档仍会永久关闭通道，不会强制移动角色、覆盖玩家命令或把玩法
  拉回离线轨迹；
- m004/m005/m006 证明的六个直接类型及 type 18/26 包装器回落次级搜索门、
  严格 `<128` 插入顺序候选、四联偏移目标、contact 暂停/恢复和逐角色存档相位；
- actor 61/62 的主对象工厂、永久 type 63/64/65 灼痕、1—7 个 type 72—76
  碎片、原版整数 Bresenham 轨迹、抛物线高度、2—4 次逐级减半弹跳，以及动作帧
  后的 type 69—71/102—104 火焰；成功对象消费五个工厂/载入调用，缺失 type 102
  消费四个构造与四个即时析构调用，活动火焰和碎片退役时再消费派生类/基类四个
  析构调用；所有分支均提交到同一会话流并随局内状态保存；

## 完成标准

只有同时满足以下条件，parity contract 中的全局随机缺口才能关闭：

1. 119 个直接调用点的所有正式关卡可达消费者都接入同一流；
2. 各消费者的调用时机、同 tick 仲裁和 actor 顺序都有原版证据；
3. 十二关至少各有一条长时 MOD/Remake 调用序列哈希与可见行为差分；
4. 已恢复的攻击间隔、自然接敌、物品、特殊攻击和性能门禁持续通过；
5. 存档恢复后继续消费的序号、值和可见结果均与不中断运行一致。
