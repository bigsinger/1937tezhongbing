本文记录为复刻实现提供约束的原版行为结论。仓库不收录原版可执行文件、IDA 数据库、反编译日志、界面图片或其他原始素材；地址级结论来自仓库外的只读分析记录 `E:\1937\original-forensics-20260719\原版行为取证报告.md`。

原版实机取证有一项可审计副作用：原程序在 `2026-07-19 00:39:05` 更新了仓库外游戏目录中的 `E:\1937\1937tzb_1229\1937M010.SAV`（388 字节，SHA-256 `82F5B83597E1D9DB959EC92FE3D97F35E82BD9A2BB589B3DD3EDCC66DA72DADE`）。该文件未进入仓库或补丁包；本记录保留此事实，便于使用者自行恢复原目录备份。

## 如何阅读证据等级

| 标签 | 含义 |
|---|---|
| `recovered` / 原版确证 | 有原程序控制流、资源字段或原版实机行为直接支持，可以作为兼容约束 |
| `mixed` | 目标、scene 或资源引用来自原版，但呈现方式包含复刻设计 |
| `remake_editorial` | 为现代可玩性新增或补写，不能表述成原版事实 |
| `unresolved_remake_default` | 原版路径已定位，但精确数值或语义尚未恢复，暂用可玩的重制默认值 |

## 四条原版绘制队列

原版不是把所有对象简单按贴图中心或世界 Y 排序。`sub_44E2D0`（`0x44E2D0`）读取 DBL sprite 的 `header[0]` 分组，`sub_44EF50`（`0x44EF50`）按固定顺序绘制：

| `header[0]` | 原版队列 | 原版规则 | 典型资源 |
|---:|---|---|---|
| 1 | 地面/固定背景 | 最先绘制，始终位于人物和正常物件后 | 地面、道路、阴影、庄稼地 a/b |
| 0 | 正常深度队列 | 与人物一起按逐层基线稳定排序 | 人物、稻谷、树、墙、箱子 |
| 2 | 空中/固定前景 | 正常队列之后绘制，始终覆盖普通人物 | 电线、炊烟、空中旗帜、建筑遮挡片 |
| 3 | 顶层 | 最后绘制 | 海鸥 |

正常队列的恢复公式为：

```text
sort_key = current_world_y - sprite_y_offset + current_frame_layer_baseline
```

`sub_44E000`（`0x44E000`）只在左侧深度严格大于右侧时交换，因此相同深度保持原插入顺序。当前 Godot 运行时通过 `world_depth.gd` 把四队列映射到互不重叠的 CanvasItem z 区间，并把正常对象基线压缩到中间区间。

庄稼遮挡需要区分两种资源：

- `庄稼地a/b.spr` 的 `header[0] == 1`，是地面底片，不能覆盖人物；
- `稻谷.spr` 的 `header[0] == 0`，是独立竖向稻秆，和人物按脚底基线排序。人物在稻秆后方时可被局部遮挡，在前方时应盖住稻秆。

当前实现修正了把整块庄稼地按 Y 放进人物队列的问题，也不再绘制人物到移动目标之间的黄色连线。关键修复不只在渲染端：`ImportedLevelData` 现在保留并校验转换结果中的 `database_header_values`。m000 真实资源回归确认 22 个 DBL 336/337 庄稼底图为 queue 1 固定背景、70 个 DBL 335 稻谷为 queue 0 正常基线对象；完整真实资产套件持续检查这些数量与队列约束。多层 SPR 的逐层 baseline 尚需继续做像素级对照；现在的单层静态对象以导出的 `reference_y` 为近似基线。

### 关卡选择与战役进度的证据边界

稳定 MOD 的 `选择关卡.ps1` 会把所选编号写入进程环境
`M1937_START_LEVEL`；输入代理再通过 SDK 的十二条 `MissionRoute` 进入对应
正式关卡。这是补丁提供的自由选关能力，不是原版可执行文件中已经确证的
“逐关解锁菜单”。因此 Remake 把两者明确分开：

- 自由选关用于 MOD 对照、开发测试和任意关试玩，开始关卡本身不写完成度；
- 真正收到任务胜利后才记录本关，并将现代顺序战役的最高可用关推进一关；
- 目前没有把该现代完成度格式宣称为原版 SAV/SI 的逐字节复刻。

若后续恢复出原版战役档案字段，应以差分样本升级这条证据，而不是从文件名或
现有补丁启动器反推。

### S / B 命令的地址级语义

`S` 的直接目标不是友军。`sub_44C050` 只让
`RuntimeActorV1 +0x188 == 0` 且 `+0x074 == 1` 的存活敌军通过。点击后
`sub_44FED0` 清除全体选择并选择该敌军，使其当前朝向对应的两段扇形视野
持续可见。点击空地则创建 runtime type 90；`sub_4503D0` 若已找到 type 90
就只移动原对象，因此全世界至多一个观察标记。其资源由 DBL 1008 确认为
`检测视线精灵.spr` / GFL 341。

敌军 AI 在 `sub_45C320` 中同时使用当前方向感知场 `sub_468D40` 和 L2
遮挡线 `sub_45A2A0` 判断该标记，并由 `sub_45C710` 的 `rand() % 2 > 0`
门控轮询。第一次有效检测会清除原选择、选中检测者并删除 type 90；该标记
不进入存档，也不留下持久化记录。Remake 使用同一 Windows CRT 随机步进，
从而保留 50% 门控同时使回放可重复。

`B` 的目标过滤与之相反：必须满足 `+0x188 == 1` 且 faction 为 1。
`sub_458520` 会先按正常 A* 路线接近尸体；横向 32、纵向 16 的导航格在
两轴都相差不超过一格时立即视为可操作。到位后角色面向尸体、计数器清零、
上限写 100；`sub_456CD0` 先递增并在计数器严格大于 100 时完成，所以
尸体在第 100 次推进仍存在，第 101 次才被替换。

完成时原尸体被隐藏，原位置创建 runtime type 78；DBL 1001 将其确认为
`藏尸处.spr` / GFL 64。尸体 `+0x228` 物品容器和 `+0x22C` 武器容器都会
独立复制到 type 78，有任一容器非空时其状态设为 3。Remake 同样保留两个
容器、允许队员近距离取回，并把 type 78 与未完成的 B 命令写入存档。

### 普通攻击分发与低伤害免疫

`M1937.exe` 的 `sub_456DF0` 按 attack type 1—7 分发直接 actor 伤害。
`sub_45F000` 以双方 `+0x108/+0x110` 坐标各自相差不超过 1 判断目标格
是否重合；直接 actor 路径和坐标弹道路径不能混为一谈：

| attack type | 直接 actor 伤害 | 直接调用次数 | 坐标路径投射数 |
|---:|---:|---:|---:|
| 1 | 2 | 1 | 1 |
| 2 | attacker runtime type 1 为 16，否则 2 | 1 | 1 |
| 3 | 2 | 1 | 3 |
| 4 | attacker runtime type 56 为 1，否则 8 | 1 | 0 |
| 5 | 16 | 1 | 0 |
| 6 | 8 | 1 | 1 |
| 7 | 1 | 1 | 1 |

所以机枪的三条散布弹道不是同一 actor 的三次扣血。普通手枪、步枪和机枪
坐标弹道都通过 `sub_4656C0(effect=1, step=64, damage=2)` 创建；这条
mode 0 路径没有飞行 actor/SPR，逐 tick 先查 L3 actor、再查 L2 障碍。
机枪对活动 actor 中心使用 `0/-1/+1` 度，对纯坐标使用 `0/-2/+2` 度；
`sub_45DD50` 按 `x=source.x-trunc(cos(a)*d)`、
`y=source.y-trunc(sin(a)*d*0.5)` 计算散布端点。命中 actor、障碍或终点后，
effect 8 通过 `sub_465310` 创建 actor 60，首匹配 GFL 306
`火花效果.spr`，4 帧各保持 2 tick 后销毁。上述不可见弹路、独立散布命中、
火花生命周期及存读档现均已接入 Remake。

伤害入口 `sub_458700` 在伤害小于 32 时跳过 runtime target type
34/86/87/88/94/95/96/97；32 及以上不受此门槛影响。Godot 侧由
`LegacyCombatRules`、SDK 侧由 `OrdinaryCombat.hpp` 固化同一组规则；
`AttackTargetCellCoincides`、`OriginalEndpointFromAngle`、
`CreateOneShotEffectActor` 和 `UpdateOneShotEffectActor` RVA 已进入地址清单。

### 坐标警戒与五点调查

`sub_45DDA0` 不是“把看到的玩家指针发给所有友军”。它遍历全局 actor
插入顺序，只接受存活 faction 1、runtime type 不为 91，且不处于
`contact_state == 1 && target_lost != 1` 的对象；源对象自己也跳过。玩家
阵营源写源坐标，其他源若有 `+0x214` 目标则写目标当时坐标，接收者只得到
`+0x198/+0x19C` 地面命令及活动标志，不会得到目标指针。

范围同样不是普通圆。`sub_45A7C0` 先计算源到接收者的屏幕角 `a`，构造
`(R*cos(a), R*0.5*sin(a))`，返回该点的欧氏长度；`sub_45DDA0` 再以严格
`distance < boundary` 比较。普通攻击参数为 640，faction 1 死亡路径
`sub_4585F0` 为 256，actor 62 爆炸路径 `sub_4554A0` 为 800，均不检查
L2 声音遮挡。

`sub_45E4B0` 最多调用 `sub_45D060(this, 32)` 五次。每次从当前位置取
`x=±(rand()%32)`、`y=±(rand()%16)`，夹在地图边缘内 16 像素，再把下一
等待上限设为 `rand()%160+40`；状态机使用严格 `counter > limit`。Remake
使用同一 MSVC 随机步进、五条路线和可存档计数。

这里保留一条不能被静态调用图覆盖的运行证据：m000 稳定 MOD 中 scene
1598 两次步枪攻击时，相邻 scene 1433 仍保持原巡逻目标且两个目标指针都
为空。说明普通射击的警戒命令还会与持久巡逻控制器发生同 tick 仲裁。
Remake 原版模式保留该已验证可见结果；在仲裁入口恢复前，不把函数调用图
误实现成“敌军每次开枪都强制全队放弃巡逻”。

### AI 站立动作循环

actor 构造函数 `sub_450AC0` 将待机计数清零，把首轮上限设为
`rand()%160`。`sub_4587E0` 在 AI 到达路线点时推进计数；周期结束后清零，
并把下一上限设为 `rand()%160+40`。主更新 `sub_458A80` 只对 AI 标志
`this[32]` 有效、没有移动/特殊控制且不在武器动作中的角色执行视觉切换：
令 `third = limit/3`（整数除法），计数位于 `[third, 2*third)` 时请求
action 2 `stand_action`，首尾两个三分之一区间请求 action 1 `stand`。
随后仍通过 `sub_41C060(action, direction)` 查找精确 serial；缺少方向时
保持当前动画，不能镜像补帧。

十二关运行时实际引用的 39 个角色 SPR 中，30 个包含完整八方向
`stand_action`，共 240 组、1,912 帧。Remake 已按原 30 Hz 角色逻辑计数
播放并保存计数、帧相位和随机状态；当前使用逐 scene 的 MSVCRT 随机流来
保证回放确定性，待所有原版 `rand()` 调用点恢复后再并入全局调用顺序。
attack type 8/10 由 `sub_4566E0` 映射到 action 8 `active_action`；角色资源
中唯一一套该动作的 8 个方向、72 帧也已进入真实资产门禁。

### SPR triplet 与角色移动/寻路

SPR frame group 在文件中连续保存三组三元组，但运行时语义不是早期解析器
采用的 primary/secondary/tertiary。文件第 1、2、3 组分别写入 runtime
primary、tertiary、secondary；因此 `sprite.json` schema 3 已修正后两组
名称，schema 1/2 在 Godot 入口交换迁移。互异三元组的合成文件测试会拒绝
再次把两组读反。

`sub_455E30` 的角色移动读取 secondary 第 0/2 分量，以 60 Hz actor tick
分别钳制 X/Y 到当前路径点。walk 使用原值，run 乘 3，crawl 使用自己的
secondary；常见 `[2,1,1]` 因此得到 walk/crawl 120/60 px/s 和 run
360/180 px/s。两个分量独立意味着对角移动不是按欧氏向量归一化。

每个 tick 只消费当前路径点：不足一个分量时钳制到目标并推进游标，但未用
余量不带到下一个路径点；若恰好剩 2/1 像素，则必须在同 tick 判定到达，
不能多空耗一帧。稳定 MOD 的 m000 scene 1418 在一秒内从
`(3478,1301)` 到 `(3358,1361)`，即精确 `(-120,+60)`；树边轨迹又验证
1 像素余量不会跨段携带。

同一规则使八个相邻导航格的 actor tick 成本相同。复刻据此使用
Chebyshev 启发式、北/东北/东/东南/南/西南/西/西北的确定性扩展顺序，
保留原版单侧可走时的贴角斜行、双侧阻挡时的禁穿角，以及轴向直线和平局
阶梯的停步朝向。无遮挡命令、树边绕障碍、46 名敌军两段巡逻运动学和
scene 1598 自然接敌四条稳定 MOD 轨迹均为严格零差异门禁。

### 敌军尸体发现与增援

`sub_45C4C0` 按全局插入顺序选择第一个 faction 1、已死亡、`+0x258 == 0`
的尸体，而不是选择最近尸体。候选必须处于观察者当前方向的外视野带
`sub_468D40 == 2`，并通过 L2 遮挡线；认领时立即把尸体 `+0x258` 置 1，
第二名观察者不能重复处理。观察者进入 contact state 3、接近尸体并等待
`rand()%40+40` 且严格超过上限，随后转入上述五点调查。

首次发现还会置全局警报，并由 `sub_45E2A0` 在最近的 runtime type 93
标记附近创建两名 runtime type 6 增援。Remake 保留动态 scene/serial、
领导者、来源标记、尸体认领与掩埋互斥关系，并把整条生命周期写入局内存档。

### 可开关门与源层足印

DBL/GFL 中已确认七组关闭/打开资源：175 的 791→792、176 的 793→794、
224 的 146→147、225 的 148→149、483 的 785→786、485 的 787→788，
以及 409 的 838→839。每组 SPR 的关闭/打开锚点不同，不能只替换纹理而
沿用同一个左上角。

Remake 先按各自原锚点把两张 alpha 图放回世界，再取“关闭可见、打开透明”

## 系统菜单、十槽存档与音量

原版 `Esc` 菜单的保存、读取各有 10 个槽位，后续由鼠标操作，`Esc` 或右键返回上一级。当前复刻也提供 10 个手动槽位，另保留 `quick` 快速槽和 `autosave` 自动槽；覆盖已有手动存档需再次确认。菜单中的“读取”始终打开多槽选择器，只有复刻扩展 `Ctrl+F9` 会按时间读取最新有效槽。任务失败时画面灰化并打开标题为“任务失败”的菜单，正文模板为 `任务失败：%s\n可重新开始本关，或从多槽存档选择器读取进度。`（`%s` 为失败原因）；继续和保存不可用，重玩与读取可用，失败状态也不能写入有效存档。已掩埋敌人的 scene、type 78 藏尸处双容器，以及尚未完成的 B 命令执行者/目标/计数会随局内状态保存；一次性的 type 90 观察标记明确不保存。

复刻设置 schema 当前包含：

- 总静音开关以及主音量、音乐、音效、语音四条独立滑杆，分别接到 `Master`、`Music`、`Sfx`、`Voice` 总线；
- 全屏跟随当前桌面分辨率、字幕、关卡简报和鼠标边缘卷屏；
- 可持久化的按键重映射和恢复默认键位。

运行时有独立音乐/环境声播放器并路由到 `Music`；影片播放器的音轨也进入 `Music`，对白进入 `Voice`，武器、爆炸、环境事件和 UI 音效进入固定 SFX 池。媒体模态层中的 `Esc` 在松开时提交关闭/跳过，避免一次按键同时穿透到下面的系统菜单；Enter/Space 用于继续简报或对白。

以上设置、十槽选择器和 JSON 原子写入属于复刻产品功能；除十槽菜单结构外，不应归因于原版。
