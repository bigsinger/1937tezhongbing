# Remake 现代化改造验收报告

## 1. 验收范围

本报告只验收 `Remake`，不借用 `Patch` 或 `Mod` 的运行时代码来代替实现。
稳定 `Mod` 只作为十二关内容来源和经典行为对照。验收对象包括：性能、资源与
发行、显示设置、运行服务边界、空间查询与感知调度、现代操作与 UI、存档、
辅助功能、AI 反馈、教育内容、便携构建和回归测试。

验收基线日期为 2026-08-05，Godot 版本为 4.7.1 stable。自动探针只向 Godot
自己的目标视口注入事件，不捕获、裁剪、锁定或移动桌面鼠标。

## 2. 实施结果

### 性能与运行服务

- `RuntimePerformanceMonitor` 记录帧、物理、导航、绘制、对象、内存、载入阶段
  和首次操作延迟，并可由 F10 诊断层查看。
- 武器栏、物品栏、字体、图标和常用声音在关卡准备期预热，避免首次点击承担
  同步解码。
- `NavigationRequestQueue` 对单帧寻路设置预算；密集关卡另有预热、路径后缀
  复用和静态不可达预检。多格移动足迹使用紧凑位图，且相同关卡重建时复用
  不可变净空基线；开门造成的变化只修改当前关卡副本。
- `WorldSpatialIndex` 为角色、敌军、尸体、掉落物、门和投射物提供分桶查询；
  投射物、爆炸和交互不再无条件扫描整个活动对象集合。
- `PerceptionScheduler` 按角色稳定身份错峰执行感知；小地图只更新变化的标记。
- `LevelLoadPipeline` 在工作线程读取并解析 JSON、读取地形图像字节，主线程
  负责 Godot 节点、纹理和场景对象创建，并向产品壳报告阶段进度。
- `GameCommandBus`、`RuntimeServiceHub`、检查点、诊断、设置应用、空间索引和
  感知调度已经从组合根中形成独立、可测试边界。

### 显示、操作与界面

- 支持窗口、桌面全屏和无边框最大化，支持 `Alt+Enter`、VSync、帧率上限、
  自定义窗口尺寸、UI/文字缩放和安全边距。
- 经典与现代 RTS 操作方案并存。现代方案增加控制组、相机书签、双击选择同类
  单位、中键拖动及可配置镜头速度；经典方案继续保持原版快捷键语义。
- 攻击预览显示武器、距离、命中率、射程、声音影响和失败原因；不可达、距离
  不足、弹药不足、遮挡及未命中都有明确反馈。
- 设置页和主要产品界面支持键盘焦点；1024×768、16:10、16:9、21:9 和 4K
  的布局按安全视口与缩放矩阵自动验证。
- 提供高对比度、大光标、视野纹理区分、完整字幕、减少闪光、减少镜头运动、
  失焦暂停、弱化暴力和教育模式。
- 新增产品文本经 `LocalizationService` 和 `tr()` 进入中英文等键目录，不依赖
  颜色作为唯一信息通道。

### 规则、AI 与教育内容

- “规则集”与“难度”已经分离：经典/现代规则不再被难度选项隐式切换。
- 难度包含剧情、普通、困难和自定义；自定义可独立调整敌军命中、反应、感知、
  搜索、警报和增援系数，玩家武器规则保持独立。
- 现代 AI 使用怀疑值、记忆衰减、最后已知位置、有限搜索区域、警报传播和增援
  预算；开发诊断层可显示感知、声音、路径和 AI 状态。
- 十二关均有历史背景、目标语境和“史实与艺术加工”说明；历史档案页包含人物、
  地点、武器与事件词条，任务结算页记录耗时、伤亡、警报、命中和可选挑战。

### 存档、诊断与内容安全

- 存档升级到 schema 2，记录规则集、难度、运行时/content/workspace 身份，并
  保留 schema 0/1 迁移和未来版本只读保护。
- 关卡开始和关键目标可生成滚动检查点；写入仍采用临时文件、回读校验、原子
  替换、备份和损坏主文件隔离。
- 多槽选择器使用轻量索引读取元数据，不需要为显示列表解析完整世界快照。
- 内容包使用版本化 manifest、长度和 SHA-256 验证；路径越界、缺失、截断和
  损坏内容会在进入关卡前被拒绝。
- 玩家可导出隐私安全的诊断包，包含版本、设置白名单、最近命令、性能摘要和
  可复现种子，不包含按键映射、存档正文或本机私人路径。

## 3. 自动化证据

### 长时间稳定性

发布前执行 30 分钟、三轮十二关切换及反复存读档：

```powershell
.\tools\Run-StabilitySoak.ps1 `
  -GodotExecutable D:\Godot\Godot_v4.7.1-stable_win64_console.exe `
  -DurationSeconds 1800 -Passes 3
```

最终无交互验收在同一参考机上持续 31.81 分钟并覆盖十二关三轮：

|---|---:|---:|---|

| 最慢冷 / 热载入 | 3798.0 / 2943.9 ms | ≤ 6000 / 3500 ms | 通过 |
| 第二轮静态内存增长 | 3.911 MiB | ≤ 8 MiB | 通过 |
| 物理存档 / 读档 | 36 / 36 次 | 每次关卡访问各一次 | 通过 |
| 崩溃、脚本或引擎错误 | 0 | 0 | 通过 |
| 全局鼠标控制 | 否 | 必须为否 | 通过 |

可审计摘要位于
`validation/baselines/remake/stability-soak-30-minute-v1.json`；被 Git 忽略的
完整报告由摘要中的 SHA-256 固定身份。为消除首次冷加载尖峰，角色动作加载器
会在一次关卡重建内复用只读 `sprite.json` 文档，并在重建完成后释放解析缓存；
动作纹理仍按会话复用，因此没有以长期内存增长换取加载速度。

### 功能与产品回归

`Verify.ps1` 是最终总门禁，覆盖：

- 原始资源守卫、.NET Release 构建和资源格式测试；
- 十二关内容身份、导航、门、物品、背包、武器、投射物、战斗、任务成功/失败、
  导演、媒体、存读档和确定性行为差分；
- 真实十二关输入旅程、自然失败矩阵、世界事件闭环和 m004 密集导航压力；
- 现代化服务、显示/辅助矩阵、产品壳、焦点生命周期、损坏内容拒绝和诊断包；
- 1024×768、1920×1080 各 13 张压缩窗口截图的尺寸、解码、亮度与唯一性；
- 48 秒十二关真实窗口性能探针和最终场景冒烟。

已单独通过的关键回归包括：十二关世界循环 809 项、十二关输入旅程 427 项、
任务失败矩阵 322 项、真实资源 26,127 项、门与静态导航 895 项、原版 HUD
249 项、战斗任务 203 项、世界交互 142 项、现代化服务 51 项、显示/辅助
矩阵 45 项，以及 m004 的 229 次密集寻路查询。完整发布结论仍以同一提交上的
最终一次 `Verify.ps1` 为准。

2026-08-05 的最终全量运行输出 `All remake checks passed.`，耗时约 39.9 分钟。
其中 48 秒窗口冒烟采集 2,161 帧，P95/P99 为 17.433/18.977 ms，207 个输入
事件只进入目标视口；1024×768 与 1920×1080 各 13 张产品截图均通过尺寸、
解码、亮度与唯一性门禁，并使用 Windows OCR 在本地处理，没有上传原图。

## 5. 发布判定

发布候选必须同时满足：

1. 30 分钟稳定性摘要为 `passed`，日志无 `SCRIPT ERROR` 或 `ERROR:`；
2. 最终 `Verify.ps1` 输出 `All remake checks passed.`；
3. `Build-Playable.ps1 -AssetMode Copy` 使用正式导出模板，PCK 与导出 EXE
   两条冒烟均通过；
4. ZIP、`SHA256SUMS.txt`、ZIP 的 `.sha256` 和 `build-info.json` 均生成；
5. 从独立 Copy 目录启动不依赖 Junction、源码目录或开发机绝对路径；
6. Git 仅提交源码、文档和自动化，不提交 LocalAssets、日志、存档或临时截图。
