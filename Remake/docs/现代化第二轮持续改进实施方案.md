# Remake 现代化第二轮持续改进实施方案

状态：全部完成（WP0—WP12、产品回放、完整 Verify、严格性能门禁与
30 分钟稳定性门禁均已通过）

方案基线：main / daae74b

编制日期：2026-08-06

开始实施：2026-08-08

实施记录：[现代化第二轮实施日志](现代化第二轮实施日志.md)

适用范围：仅 Remake 及其必要的 MapEditor 对接面

## 1. 目标与批准范围

本方案把已经批准的改进范围拆成可连续实施、可逐批验证、最终统一验收的工程计划。
实施目标不是完成某一个阶段，而是完成本文全部工作包并通过最终完成定义。

批准实施的范围：

1. 第一阶段全部内容：
   - 固定帧模拟时钟；
   - 正确且低开销的性能监控；
   - 事件驱动的世界空间索引；
   - 渐进拆分超大核心脚本。
2. 第二阶段全部内容：
   - 预防式多人移动协调；
   - 完整产品文本本地化；
   - 低干扰潜行信息反馈；
   - 从最近检查点快速重试；
   - 分层、可并行的开发验证流程。
3. 第三部分除“教育体验深化”外的全部内容：
   - 战术暂停与命令队列；
   - 现代 AI 战术深化；
   - Remake 原生关卡内容生态。

明确排除：

- 本轮不实施教育体验深化，不增加知识问答、教师报告或新的史料编辑工作；
- 不修改 Patch 和 Mod 的运行时代码；
- 不恢复向旧 VWF 写回新地图的路线；
- 不向 Git 上传完整游戏包、原始游戏素材、LocalAssets、绿色 ZIP、EXE、PCK、
  本地存档、日志、遥测或机器专用配置；
- 未经用户明确命令，不生成最终绿色 ZIP；
- 不调用、移动、裁剪、锁定或限制系统全局鼠标。

## 2. 当前基线与主要问题

当前版本已经具备十二关可玩闭环、现代显示设置、存档、导航、战斗、任务、媒体、
辅助功能、现代 AI 基础和完整自动化门禁。最近一次验证中，十二关窗口性能保持在
约 17.6 ms P95，未出现超过 50 ms 的帧，因此本轮不以“更换引擎或重写渲染器”
作为默认方案。

仍需解决的结构性问题：

- Main._process 负责推进任务、导演和 AI 协调器计时，而移动与战斗在固定物理帧
  推进，玩法结果可能受到渲染帧率影响；
- RuntimePerformanceMonitor 的 frame 指标主要是 Main 脚本区段 CPU 时间，
  不能代表完整呈现帧，采样窗口还使用头部删除；
- WorldSpatialIndex 每 0.1 秒轮询全部活动角色，存在周期分配和短暂位置滞后；
- main.gd、squad_unit.gd、enemy_unit.gd、game_shell.gd 分别承担过多职责；
- 当前卡位恢复能够脱困，但缺少在门口、树林和窄路发生冲突前的协作预约；
- 部分菜单、状态文字和工具提示仍为脚本内硬编码中文；
- 现代潜行状态已经存在，但玩家对怀疑、搜索、最后发现位置和噪声后果的感知不足；
- 自动测试全面但总门禁接近四十分钟，不利于高频开发反馈；
- 当前回放测试主要验证合成事件，不是实际玩家命令流的产品级回放；
- 任务和地图运行时已经数据化，但还没有安全、版本化、可由编辑器导出的现代内容包。

## 3. 实施原则

### 3.1 经典与现代规则隔离

- 经典规则继续保持已经审计的确定性行为；
- 修复帧率依赖、数据损坏、输入穿透、卡位和性能问题可以同时惠及两种规则；
- 战术暂停、现代协同 AI、风险路径预览等新增玩法默认只在现代规则启用；
- 新功能通过策略对象或能力开关接入，不在核心循环中继续堆叠分散的模式判断；
- 每次存档记录规则集、内容身份、模拟时钟和相应功能版本。

### 3.2 渐进抽离，不一次性推倒

每次只抽离一个可以独立测试的垂直切片。旧调用面在迁移期间保留兼容门面，
确认调用者全部迁移并通过门禁后再删除。不得为了缩短文件而复制状态或形成两个
事实来源。

### 3.3 模拟与表现分离

- 会影响胜负、AI、任务、命中、物品、导航和存档的状态只由固定模拟 tick 推进；
- 镜头、光标、动画插值、界面过渡和非决定性装饰由渲染帧推进；
- 表现层不得直接写任务和战斗状态，只能提交命令或消费事件；
- 暂停时模拟时钟停止，界面、镜头和计划预览仍可运行。

### 3.4 测量后优化

- 不因推测更换 Godot Compatibility 渲染器或原导航语义；
- 所有性能改动必须有改动前后同场景数据；
- 优化不得放宽 L2 视线、L3 移动、门状态或动态占用的权威约束；
- 无法在当前硬件验证的项目明确标记，不伪报为已验证。

### 3.5 安全与仓库边界

- 所有自动输入仅发送到目标 Godot 视口；
- LocalAssets 和 QA 输出继续处于 Git 忽略目录；
- Git 提交按源码、测试、文档和必要小型配置精确暂存；
- 工作区中既有的 Mod 存档、配置和遥测属于用户数据，不得覆盖或提交。

## 6. 工作包 1：固定帧模拟时钟与确定性调度

### 6.1 新增边界

新增建议文件：

- game/scripts/simulation_clock.gd
- game/scripts/simulation_coordinator.gd
- game/scripts/simulation_system.gd
- game/scripts/scheduled_game_command.gd

SimulationClock 使用整数 tick，频率固定为 60 Hz。所有玩法持续时间在数据入口
转换为 tick，运行时不再用累计渲染 delta 决定结果。

### 6.2 迁移顺序

1. 引入 clock 和只读 tick，不改变现有系统行为；
2. 把 MissionState、MissionRuntime、MissionDirectionRuntime 和
   MissionAiCoordinator 的玩法计时迁移到固定 tick；
3. 把掩埋、特殊对象、投射物、警报、搜索、攻击冷却等剩余玩法计时统一登记；
4. 玩家输入先转换为 ScheduledGameCommand，在下一个确定性 tick 提交；
5. 规定同 tick 顺序：
   - 接收已排定命令；
   - 更新门和动态世界状态；
   - 处理移动提案与预约；
   - 提交移动；
   - 处理感知、AI 与警报；
   - 提交战斗、投射物和爆炸；
   - 发布任务事件；
   - 更新任务胜负和检查点；
   - 生成表现事件；
6. 节点原有 _physics_process 在迁移完成后只转发或关闭，避免同一系统推进两次；
7. 存档增加 simulation_tick、command_sequence 和必要的待提交命令状态。

### 6.3 兼容规则

- 原版 world tick 和 MSVCRT 随机调用顺序保持现有证据语义；
- 经典模式不启用新的战术命令队列，但仍使用固定调度器保证帧率无关；
- 媒体模态、Esc 菜单和失焦暂停不推进模拟 tick；
- 读取旧存档时安全初始化 tick，不重放已经结算的命令。

### 6.4 验收

- 同一命令序列分别在 30、60、120 和不限渲染帧率运行，最终状态哈希一致；
- 任务限时、警报延迟、搜索持续和增援时机只允许相差 0 tick；
- 暂停十秒后恢复，玩法状态不前进；
- 保存后读取，下一 tick 的随机、AI、任务和投射物结果一致；
- 十二关经典轨迹门禁不回退。

## 7. 工作包 2：真实性能监控与长帧归因

### 7.1 工作内容

- 使用固定容量环形缓冲替换 PackedInt64Array 头部删除；
- 将指标拆分为：
  - 呈现帧间隔；
  - Main 脚本 CPU；
  - 物理模拟；
  - AI 与感知；
  - 导航与预约；
  - 世界交互；
  - UI；
  - 资源读取和节点构建；
- 使用 Godot Performance 指标记录渲染时间、Draw Call、对象数、内存；
- 当呈现帧超过预算时，自动冻结前后若干秒的计数和最近命令；
- 诊断包仅保存白名单指标，不保存完整存档、个人路径和原始素材信息；
- F10 显示最近长帧责任系统、导航队列峰值、预约冲突和恢复次数。

### 7.2 验收

- 环形缓冲写入为 O(1)，长时间运行不发生持续数组搬移；
- 诊断中的 frame 与外部性能探针帧间隔误差在允许范围内；
- 合成长帧可以明确归因到指定测试系统；
- 关闭诊断叠层时，监控自身 P99 开销低于 0.10 ms；
- 诊断导出仍不包含隐私数据。

## 8. 工作包 3：事件驱动空间索引

### 8.1 工作内容

- 角色只有跨越空间桶边界时才提交索引更新；
- 出生、死亡、复活、掩埋、拾取、丢弃、门切换和切关通过明确事件登记；
- tag 字符串在注册时转换为位掩码，热查询不再重复正规化字符串；
- query_radius 和 query_rect 复用小型临时缓冲，减少每次查询数组分配；
- 开发构建保留低频完整一致性审计；产品构建不轮询全部角色；
- scene_index 映射继续由索引维护，但节点本身仍是状态事实来源。

### 8.2 验收

- 对象跨桶后同一模拟 tick 内可在新位置被查询；
- 原位置不再返回重复对象；
- 出生、死亡、尸体、掉落物和门的注册数无泄漏；
- 十二关空间查询候选量和 CPU 时间不高于基线；
- 关闭轮询后，感知、拾取、爆炸和门交互结果保持一致。

## 10. 工作包 5：预防式移动协调

### 10.1 新增服务

新增 movement_reservation_service.gd，采用短时间窗、确定性预约，而不是把动态
角色永久写成静态障碍。

每个移动 tick 分为：

1. 角色提出下一位置和若干后备位置；
2. 服务按优先级和等待年龄仲裁；
3. 获准角色统一提交；
4. 被拒角色保持位置、增加等待年龄，并在必要时请求局部改道。

### 10.2 优先级

默认顺序：

1. 玩家直接命令和正在脱离危险的角色；
2. 近战接敌、追击和救援；
3. 剧情护送和任务动作；
4. 小队领队；
5. 跟随者；
6. 普通巡逻。

等待年龄会逐步提高有效优先级，避免低优先级角色永久饥饿。scene_index 仅作为
最后的确定性决胜，不作为永久特权。

### 10.3 窄路与队形

- 自动识别门、桥、树林通道和单格瓶颈；
- 同方向角色形成通行批次，反方向角色等待当前批次离开；
- 巡逻队共享主走廊，跟随者使用动态槽位，不抢占领队下一格；
- 队形在狭窄区域自动收缩，离开后逐渐恢复；
- MovementRecoveryPlanner 继续保留，但只作为异常兜底。

### 10.4 验收

- 双向通过单门、十人树林通道和交叉路径夹具无永久死锁；
- 任何角色最长等待有上限；
- 不瞬移、不穿 L3、不斜穿贴角、不跨关闭的不可交互门；
- 基准关卡卡位恢复触发率相对现有基线明显下降；
- 敌人、护送者和玩家路径不会出现位置回退式抖动。

### 11.2 UI 设计

- 使用容器和最小尺寸，减少硬编码屏幕坐标；
- 工具提示增加统一延迟、最大宽度和键盘焦点显示；
- HUD、字幕、任务提示和战术计划层统一通过安全区服务排布；
- 1024×768、1280×800、1920×1080、2560×1080、3840×2160 均不遮挡；
- 保持大光标、高对比度、文字缩放和色觉辅助能力；
- 不增加大圆圈选中效果。

### 11.3 验收

- 简体中文和英文完整走通主界面、关卡、失败、胜利、设置和存读档；
- 玩家可见硬编码字符串扫描为零，明确白名单除外；

- 多分辨率截图不截断、不重叠、不穿透世界输入。

## 12. 工作包 7：潜行信息反馈

### 12.1 默认表现

- 只有被 S 观察、鼠标悬停、当前交战或进入警觉的敌人才显示反馈；
- 头顶使用窄小怀疑条和简洁状态标记，不遮挡人物精灵；
- 不绘制活物脚下大圆圈；
- 最后发现位置用短时、低透明度标记，过期自动消失；
- 视线继续使用动态空心扇形，红色近区和绿色远区保留线型差异；
- 噪声预览只在准备开枪、投掷、丢弃诱饵或战术计划时显示；
- 路径风险预览按将经过的视线/噪声风险分段着色，可在设置中关闭。

### 12.2 数据来源

表现层只读取 EnemyStrategy 的公开快照：

- awareness_state；
- suspicion_ratio；
- last_known_position；
- memory_ticks_remaining；
- assigned_search_sector；
- hearing_radius；
- current_visibility_band。

表现层不得直接修改 AI。

### 12.3 性能要求

- 只有状态变化、朝向跨量化档或遮挡网格版本变化时重建视线轮廓；
- 不填充整个扇形实体；
- 路径风险使用缓存的格级风险场，不对每条像素路径重复射线；
- 默认关闭时不得产生持续射线或绘制开销。

### 12.4 验收

- 玩家可以明确区分怀疑、搜索、战斗和归队；
- 匍匐在远绿色区不被发现、进入近红色区仍被发现；
- 墙体遮挡在判定和表现上保持一致；
- 反馈关闭后不影响玩法状态和确定性哈希；
- 多敌人观察场景达到现有帧预算。

## 13. 工作包 8：最近检查点快速重试

### 13.1 交互

失败菜单依次提供：

1. 从最近检查点重试；
2. 重新开始本关；
3. 读取手动存档；
4. 返回关卡选择。

没有有效检查点时第一项灰化并说明原因。

### 13.2 数据安全

- 检查点仍使用滚动槽，不覆盖十个手动槽；
- 写入采用临时文件、回读校验、原子替换和备份；
- 最近有效检查点索引只读取轻量元数据；
- 检查点必须匹配关卡、规则、难度、内容身份和存档 schema；
- 失败状态本身不得覆盖最后一个可恢复检查点；
- 读取后恢复 SimulationClock、AI、任务、预约和战术命令队列。

### 13.3 验收

- 从失败界面一次点击即可恢复最近检查点；
- 损坏的最新检查点自动回退上一有效检查点；
- 不存在检查点时仍可重开或读取手动槽；
- 连续失败、重试和切关不增长内存或混入上一关状态。

## 14. 工作包 9：分层验证与 CI 提速

### 14.1 三层门禁

快速门禁，目标五分钟内：

- 资源守卫；
- GDScript 解析；
- .NET 编译和格式测试；
- 固定帧、交互、导航、AI、存档和 UI 核心单元测试。

内容门禁：

- 真实资源身份；
- 十二关短输入旅程；
- 门、物品、战斗、任务、存读档和视线；
- 30/60/120 帧率一致性；
- 双分辨率产品截图。

发布门禁：

- 十二关性能和内存双轮；
- 30 分钟稳定性；
- 多次换关和存读档；
- 便携构建结构与启动冒烟；
- 内容包和恶意输入安全测试。

### 14.2 工程改进

- Godot 测试按领域分片；
- .NET restore、Godot import 和合成 fixture 可缓存；
- 输出 JUnit 和机器可读 JSON；
- 单一失败显示所属工作包、复现命令和关键日志；
- Verify.ps1 保留总入口，但内部调用可独立重跑的阶段脚本；
- 长测试超时时支持从未完成分片继续，不重复已通过部分。

### 14.3 验收

- 日常代码变更能在快速门禁获得明确反馈；
- 完整门禁仍覆盖现有项目，不以提速为由删除验证；
- 每个分片无共享可变用户目录；
- CI 不需要原始游戏资产即可完成结构和合成测试。

## 15. 工作包 10：战术暂停与命令队列

### 15.1 规则边界

- 默认只在现代规则启用；
- 经典规则继续使用现有即时命令；
- 默认按键为空格，可重映射；
- 媒体模态期间空格仍由媒体层消费，不触发战术暂停；
- Esc 菜单与战术暂停是两个独立状态。

### 15.2 支持的计划命令

- 移动到位置；
- 跑步/行走/匍匐姿态；
- 攻击角色；
- Ctrl 强制攻击坐标；
- 拾取、开门、丢弃诱饵；
- 掩埋；
- 使用特殊物品；
- 等待指定 tick；
- 在同一角色队列中设置顺序；
- 多角色同步开始。

### 15.3 计划界面

- 暂停后世界灰度仅做轻量区分，不遮挡地图；
- 路径使用细线和小型编号节点，不画大圆圈；
- 每条动作显示预计时间、射程、弹药、噪声和可达性；
- 无效命令在计划阶段解释原因；
- 执行时再次校验动态条件，失败则跳过或等待，策略由命令类型决定；
- 支持撤销最后一步、清空单人队列和全部执行；
- UI 拦截点击，不允许命令穿透到世界。

### 15.4 运行时语义

- 计划命令在恢复模拟后的下一个 tick 统一提交；
- 每条命令具有 sequence、actor、precondition、timeout 和 failure_policy；
- 资源消耗在实际执行帧发生，不在计划时提前扣除；
- 目标死亡、门状态变化或路径失效时采用明确降级；
- 队列、当前游标和等待状态进入存档；
- 产品级命令日志可以重放同一计划。

### 15.5 验收

- 多名角色能够同步潜入、开门、攻击和撤离；
- 暂停期间 AI、任务、投射物和计时完全停止；
- 相同计划重复执行得到相同状态哈希；
- 存读档后命令顺序和剩余等待一致；
- 经典模式行为、快捷键和轨迹不变。

## 16. 工作包 11：现代 AI 战术深化

### 16.1 证据黑板

新增 ai_evidence_blackboard.gd，保存可解释的证据，而不是共享活目标引用：

- 证据类型：目击、枪声、脚步、尸体、开门、丢弃物、爆炸；
- 坐标、发生 tick、置信度、来源阵营、传播方式；
- 随时间衰减并可由新证据刷新；
- AI 只能使用自己获得或被传播的证据，禁止全图读玩家位置。

### 16.2 通信

- 喊话：有限半径，可受特定隔音规则影响；
- 枪声和爆炸：大范围声音事件，不需要视线；
- 警报器：关卡级事件，但需要实际触发；
- 无线电：只有数据明确配置的单位可使用；
- 通信延迟、半径和接收者数量受难度策略控制。

### 16.3 搜索协同

- 根据可达区域把最后位置周围划分搜索扇区；
- 队长负责分配 lead、left、right、rear_block 等角色；
- 不让多人重复检查同一格；
- 搜索覆盖不足时扩展，证据过期后逐级降为警戒、归队；
- 门和窄路使用同一预约系统；
- 对玩家可能路径的预测只能基于最后方向、速度和可达图。

### 16.4 战斗行为

- 敌人在射程内开火，不强制贴近；
- 压制射击是真实的坐标攻击，会消耗弹药并产生声音；
- 侧翼候选必须通过导航和视线验证；
- 低生命、失去队长或缺少弹药时可切换防守/撤退策略；
- 任何难度都必须保留反应时间和清晰反馈，禁止零提示瞬时命中；
- 经典模式不构造现代黑板和战术策略。

### 16.5 调校与本地统计

开发统计记录：

- 警报来源；
- 搜索覆盖率；
- 重复搜索率；
- AI 卡位和预约等待；
- 玩家死亡位置；
- 各武器命中和弹药消耗；
- 每关失败原因。

数据仅保存在本地 QA 目录，不自动上传。

### 16.6 验收

- AI 丢失视线后不再追踪实时玩家坐标；
- 多人搜索具有不同扇区并能在超时后归队；
- 声音、尸体和开门证据按各自规则传播；
- 压制射击、包抄和增援均可由玩家观察和反制；
- 难度变化调整压力但不改变玩家固定武器命中规则；
- 存读档恢复黑板、搜索分配、警戒等级和归队目标。

## 17. 工作包 12：Remake 原生关卡内容生态

### 17.1 格式目标

定义版本化、声明式、不可执行任意脚本的 .m1937pack。它可以采用 ZIP 容器，
但必须拥有专用扩展名和严格 manifest。

建议结构：

~~~text
manifest.json
campaign.json
levels/<level-id>/level.json
levels/<level-id>/navigation.bin
levels/<level-id>/mission.json
levels/<level-id>/direction.json
levels/<level-id>/preview.webp
assets/sprites/...
assets/audio/...
localization/zh_CN.json
localization/en.json
~~~

manifest 包含：

- schema_version；
- pack_id、version、display_name；
- 最低运行时版本；
- 文件长度和 SHA-256；
- 关卡入口；
- 依赖和冲突；
- 原始来源说明字段；
- 可选能力声明。

### 17.2 安全

- 所有路径规范化后必须留在包根目录；
- 拒绝绝对路径、父目录穿越、重复大小写路径、符号链接和超限文件；
- 设置总解压大小、单文件大小、图片尺寸、音频时长和实体数量上限；
- 不加载 GDScript、DLL、EXE 或其他可执行内容；
- JSON 和 navigation.bin 使用现有严格边界验证；
- 内容包加载失败不能污染正式存档。

### 17.3 工具链

ResourceTool 增加建议命令：

- pack validate
- pack build
- pack inspect
- pack extract-safe
- pack hash

Godot 增加：

- 本地 UserCampaigns 内容发现；
- manifest 和依赖检查；
- 开发模式热重载；
- 内容包关卡选择；
- 存档记录 pack_id、version 和内容哈希。

### 17.4 MapEditor 对接

MapEditor 以同一 schema 编辑：

- 地形和静态对象；
- L2 视线遮挡；
- L3 移动障碍；
- 门和动态通道；
- 活物出生、巡逻路线和队形；
- 任务目标、依赖、失败条件和撤离区；
- 对白、镜头和 AI 指令；
- 物品、武器和掉落；
- 导航、视线、声音和任务闭环实时预览。

编辑器提供：

- 空指针工具作为默认状态；
- 选中活物后显示路线；
- 一键可达性、出生安全和任务可完成性检查；
- 在独立临时目录启动 Remake 试玩；
- 一键导出 .m1937pack；
- 不要求写回 VWF。

### 17.5 仓库策略

- 仓库提交 schema、工具、合成示例和文档；
- 不提交原版资源或完整商业内容包；
- 自动测试使用程序生成的小型 fixture；
- 用户本地打包脚本可把其合法拥有的资源装配进绿色发行物。

### 17.6 验收

- 从零创建的合成关卡可以通过编辑器导出并由 Remake 进入；
- 地图可达、门、视线、巡逻、任务成功和失败闭环均通过；
- 损坏、越界和恶意内容包被安全拒绝；
- 内容包升级和缺失依赖给出清晰提示；
- 同一包在不同路径安装得到相同内容身份；
- 打包和测试不需要向 Git 上传完整游戏资源。

## 18. 产品级命令回放与问题复现

本项作为固定时钟、命令队列和 AI 黑板的共同基础实施，不单独形成玩法入口。

### 18.1 内容

- 记录初始检查点身份、规则、难度、内容哈希、随机状态；
- 记录按 tick 排定的规范化命令，不记录原始桌面鼠标轨迹；
- 支持无界面重放和每若干 tick 状态哈希；
- 首次分歧时输出系统、角色、字段和最近命令；
- 诊断包可以选择附带短回放，但默认关闭且不包含存档正文。

### 18.2 验收

- 真实视口产生的短命令序列可在无界面环境重复；
- 战术计划、移动、拾取、门、战斗和任务事件可重放；
- 相同版本零分歧；
- 内容或版本不匹配时拒绝重放并说明原因。

## 21. 存档与数据迁移

- 任何新增持久字段都提高对应 schema；
- 迁移函数只能向前迁移，不回写旧文件；
- 未知未来 schema 保持只读拒绝，不猜测字段；
- 新存档包含 simulation_tick、命令序列、预约、AI 黑板、战术队列和内容包身份；
- 旧存档缺少新字段时使用安全空状态，不伪造已经发生的证据或命令；
- 经典存档不得在读取时自动开启现代 AI 或战术队列；
- 内容包存档只能在相同 pack_id 和兼容版本中读取；
- 检查点、quick、autosave 和十个手动槽共享校验协议，但生命周期互相隔离。

## 22. 主要风险与控制

### 22.1 固定时钟改变原版顺序

控制：先做只读 clock，再逐系统迁移；使用经典轨迹和随机调用序列逐步门禁。

### 22.2 预约系统产生新死锁

控制：等待年龄、批次通行、最大等待和恢复兜底；大量对向、环形和门口夹具。

### 22.3 脚本拆分造成双重状态

控制：组件是唯一事实来源；兼容门面只转发；每个迁移批次删除旧写路径。

### 22.4 潜行反馈造成性能回退

控制：状态变化驱动、量化缓存、默认只显示相关目标、关闭时零持续查询。

### 22.5 战术暂停破坏经典操作

控制：现代规则独立能力开关；媒体、菜单和世界输入优先级写入自动测试。

### 22.6 AI 获得不公平全知

控制：证据黑板只接受感知和通信事件；丢失视线后不保存实时目标引用。

### 22.7 内容包引入安全问题

控制：完全声明式、无脚本、路径规范化、大小上限、哈希和恶意 fixture。

### 22.8 总门禁耗时继续增长

控制：快速/内容/发布三级分片，缓存不变产物，长测支持续跑。

## 23. 最终完成定义

只有同时满足以下全部条件，才可以宣布本方案目标完成：

1. 工作包 0 至 12 以及产品级命令回放全部实现；
2. 第一、第二、第三部分批准范围没有遗留占位实现；
3. 经典模式十二关现有行为、输入、任务、门、物品、战斗、存读档和媒体门禁通过；
4. 现代模式固定帧、预约移动、潜行反馈、检查点重试、战术队列和 AI 黑板通过；
5. 30/60/120/不限渲染帧率的相同命令序列状态一致；
6. 简体中文和英文产品流程完整，本地化静态门禁通过；
