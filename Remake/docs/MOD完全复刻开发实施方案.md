# 稳定 MOD 完全复刻开发实施方案

## 1. 最终目标与完成定义

`Remake` 的目标不是“能读取原资源的相似游戏”，而是在现代运行时中完整
复现稳定 `Mod/` 的十二关产品：

- 同一地图、五层地形语义、对象、角色、出生点、巡逻路线和遮挡关系；
- 同一默认快捷键、鼠标命令、选择规则、姿态、上下文光标和操作节奏；
- 同一初始背包、世界物品、武器、弹药、攻击命中帧、伤害和特殊动作；
- 同一视线、听觉、警报、搜索、增援、攻击和返回巡逻行为；
- 同一任务目标、依赖、对白、镜头、教程、过场、成功和失败闭环；
- 同一菜单、HUD、简报、小地图、背包、声音触发和关卡推进；
- 存档后读取能够从任务任意合法阶段继续，结果不漂移；
- 现代分辨率、窗口/全屏、按键重映射、分通道音量和稳定帧时间可作为
  实现升级，但不能改变原版玩法语义。

只有十二关都通过“开始游戏 → 实际操作 → 胜利”，主要失败路径和中途
存读档也通过，且
`game/data/mod_parity_contract.json` 中不再存在 `partial` 或 `missing`，
项目才可以标记为完全复刻。格式可解析、场景可显示、自动把事件直接送进
任务状态机，都不能单独算通关验收。

## 2. 唯一内容基线

从 2026-07-29 起，仓库内稳定 `Mod/` 是复刻的唯一产品内容基线：

```text
repository-mod-12-level-20260729
├── 1937m000.vwf ... 1937m011.vwf
├── 1937Resources.GFL + InterMedia.GFL（1,394 项）
├── 1937Database.dbl
├── 1937Sound.slf
└── M1937.exe
```

`KnownStableModVersion` 对以上所有消费文件逐一做 SHA-256 校验；存档、
`rungame.ini` 和兼容 DLL 是运行状态或平台层，不参与内容身份。实验性
第 13—15 关、Sidecar 和追加简报不属于基线，也不能再次进入导入结果。

`tools/Import-ModAssets.cmd` 是默认导入入口。`Build-Playable` 若发现
`LocalAssets` 缺失或来源不是上述 profile，会自动从 `Mod/` 重建。原绿色版
目录仍可用于二进制取证，但不再作为试玩包的隐式依赖。

## 3. 证据优先级

每项行为按以下顺序定案：

1. 稳定 MOD 中真实运行的 `M1937.exe` 行为和窗口内录像/状态轨迹；
2. VWF、DBL、GFL、SLIST、SPR、SLF 等资源中的原始字段；
3. `SDK/` 中已做签名和版本门禁的地址、结构和控制流；
4. 多关卡、多对象统计得到且能被反例测试推翻的推断；
5. 为可玩性写的现代默认值。

第 5 类必须标记为 `remake_editorial` 或 `unresolved_remake_default`，默认
不能冒充原版。最终有两种处理方式：用证据替换；或放入明确命名的“现代
增强”开关，并让“严格复刻”配置完全不依赖它。

## 4. 技术路径

### 4.1 内容编译层

`.NET ResourceFormats/ResourceTool` 负责一次性把稳定 MOD 编译成版本化的
现代中间格式：

- GFL/DBL → 图片、动画、声音、对象定义与引用清单；
- VWF L1—L5 → 地形、视线、移动、事件、手工修正层；
- SLIST1 → scene、阵营、生命、方向、姿态、背包、巡逻和任务锚点；
- SPR1 → 全动作、八方向、逐帧保持、锚点和多层绘制数据；
- 任务控制流取证 → 可审阅的任务图、事件条件和世界副作用；
- 所有输出带源 profile、源索引、源字段、哈希和证据状态。

Godot 不直接猜测旧二进制格式。解析器遇到未知版本、越界、重复索引或
不匹配哈希立即停止。

### 4.2 现代运行时

Godot 运行时分为以下独立系统：

- 世界加载与四绘制队列；
- 静态导航、动态占位、门和交互障碍；
- 角色动作状态机和逐帧命中窗口；
- 选择、命令模式、快捷键和上下文光标；
- 背包、武器、弹药、拾取、丢弃、诱饵与声音；
- 站立/匍匐可见区、L2 遮挡、听觉、警报和调查 AI；
- 任务事件总线、目标图、导演、镜头和媒体；
- HUD、F1、F7、M 小地图、五列背包和菜单；
- 原子存档、设置、回放和状态哈希。

现代实现允许更高效的数据结构、批量绘制、异步资源预热和确定性状态机，
但对玩家可观察的规则保持一致。

### 4.3 MOD 对照闭环

每个尚未确认的功能都执行同一流程：

1. 在隔离副本中用稳定 MOD 进入目标关卡和场景；
2. 只向目标游戏窗口发送输入，不移动、锁定或裁剪系统鼠标；
3. 记录窗口内画面、关卡号、角色/scene 状态、输入和时间点；
4. 截图优先本地 OCR，保留压缩图，不上传无必要的原始大图；
5. 在 Remake 重放同一命令序列；
6. 比较状态哈希、角色位置、动作帧、库存、任务目标、AI 和画面基线；
7. 把通过的证据登记到 parity contract，未通过项保持 `partial`。

需要观测原版内存时，只增加版本门禁、只读探针或目标进程内的专用 hook；
不得依赖固定延时和全局鼠标自动化制造“看似通过”的结果。

## 5. 分阶段实施

### P0：内容身份与回归门禁

状态：已完成第一版。

- MOD 仅保留 m000—m011；
- 裁掉 GFL 尾部三个退役简报，原 0—1393 索引不移动；
- 新增稳定 MOD 的 17 文件内容哈希 profile；
- Remake 可直接导入稳定 MOD，试玩包会拒绝旧来源；
- SDK、选择器、任务目录和 Remake 的 12 个 id/标题/VWF 做交叉校验；
- parity contract 成为机器可读的完成度唯一入口。

### P1：取证与差分回放基础设施

- 已建立仅目标窗口的输入探针和版本化运行轨迹格式；
- 已为 MOD/Remake 输出同一 schema 的基础移动轨迹，并完成第一条严格比较；
- 继续把 MOD 已有 SDK 地址扩展为已证明身份的只读角色、背包、武器、任务和 AI 快照；
- 为加载、移动、选择、攻击、拾取、姿态、视线、声音、警报、存读档建立
  最小差分用例；
- 增加 10 分钟回放的内存、P95/P99 和 >50 ms 尖峰门禁。

退出条件：不是直接注入“任务完成事件”，而是真实输入能在两个运行时生成
可比较轨迹。

### P2：操作、动画和数值完全对齐

- 对齐 F1—F7、M/W/A/S/B/R/C、1—0、Ctrl/↑ 和鼠标全部语义；
- 完成所有上下文光标、命令落点和定时进度条；
- 对齐角色选择后的镜头定位和只在选中时显示的头顶血条；
- 对齐 20 动作、八方向、受伤、死亡、攻击命中帧和多层 anchor；
- 恢复每名角色的初始物品、三类基础武器、弹匣、备弹和拾取数量；
- 恢复 type 8/10/11 及地雷、手榴弹、炸药、油桶的精确参数。

退出条件：输入/物品/武器/动画 domain 全部 `verified`。

### P3：地图、路线、感知和 AI 完全对齐

- 十二关逐格检查 L2/L3/L5、四绘制队列、墙、门和前景遮挡；
- 恢复所有非角色足印、开关门和交互后导航更新；
- 逐条验证 516 条巡逻路线、当前节点、停留和返回路线；
- 恢复站立/匍匐两段可见扇区、方向更新与障碍裁剪；
- 恢复每类敌人的听觉、攻击距离、反应时间、警报传播和搜索结束条件；
- 恢复尸体发现、诱饵拾取、声音调查、增援、包抄和有限攻击者规则。

退出条件：十二关地图/AI 轨迹可重复，角色不穿墙、不倒跑、不在不可见区
错误发现玩家。

### P4：十二关任务逐关闭环

按 m000 → m011 顺序，每关必须具备：

- 原简报与真实初始状态；
- 所有必要任务世界事件只能由实际玩法产生；
- 一条完整胜利轨迹；
- 时间到、关键人物死亡或关卡特有条件的主要失败轨迹；
- 每个目标前后至少一个存档/读取继续点；
- 对白、镜头、教程、过场和关卡间推进；
- 弹药、任务物品和撤离条件不存在死局；
- 1024×768 和 1920×1080 的地标/HUD/遮挡截图基线。

m009 与 m011 已知原控制流缺陷同时保留“严格原版”和“修正规则”数据，
默认策略必须在设置中明确，不能悄悄混用。

### P5：产品化与最终发布

- 难度、现代增强和严格复刻配置明确分层；
- 十槽存档、快速档、自动档和版本迁移通过十二关中断点测试；
- 窗口、无边框、全屏、多显示器与 IME 屏蔽通过 Windows 10/11；
- 1920×1080/60 FPS：P95 ≤ 16.7 ms、P99 ≤ 25 ms，无正常游玩同步加载
  >50 ms 尖峰；
- 生成自包含试玩包、清单、版本信息和跨机器验收报告；
- 以 `Test-ModParityContract.ps1 -RequireComplete` 作为发布硬门禁。

## 7. 当前真实状态

现有工程已经具备完整资源管线、十二关浏览和任务图、导航/动态占位、实际
战斗、背包/投射物、基础 AI、菜单/小地图、存读档和本地试玩包，因此不是
从零开始。

但当前仍有编辑性对白、未定特殊动作参数、未完成的 S/B 语义、十一关视觉
基线和十二关真实完整通关轨迹。它们已全部写入
`mod_parity_contract.json`，不会因“自动测试能直接发送任务事件”而提前
标记完成。

## 8. 已落地的 MOD/Remake 差分闭环

2026-07-29 已完成 `m000-basic-movement-v1` 与
`m000-obstacle-route-v1`，它们不是只在 Remake 内部自测：

- `SDK/schemas/runtime-parity-trace-v1.schema.json` 固定跨运行时轨迹格式；
- `Patch/analysis/tools/ModRegressionProbe.cs` 在隔离的稳定 MOD 中采集轨迹；
- `validation/baselines/mod/` 保存两份可审阅的 MOD 基线；
- `game/tests/parity_runtime_probe.gd` 在 Remake 中重放相同的地面命令；
- `tools/Compare-RuntimeParityTrace.ps1` 比较关卡身份、检查点、角色身份、
  位置/目标、移动向量、朝向和时间区间；
- `tools/Run-RuntimeProbe.ps1` 与本地真实资源 `Verify.ps1` 均采用严格比较，
  一旦既有基线产生差异就失败，而不是只输出警告。

探针不移动、锁定或裁剪系统鼠标，不抢占桌面输入；MOD 侧只读取目标进程
快照，并把命令投递到该测试窗口的私有回放队列。首条轨迹确认强子从 MOD
原始位置执行两次无遮挡命令时，与 Remake 在 12 像素移动容差内零差异；
由 0.75 秒位移样本校准出的当前跑速为 260 px/s。

第二条轨迹覆盖第一关开局树丛：原版允许在一个正交侧格开放时贴着单侧
障碍斜行，但两个侧格都阻挡时仍禁止穿角；绕开树木后会尽早回到原移动
走廊，而不会沿等价 A* 路线长期偏移。Remake 现用同一斜行规则，并对
Godot 返回的等价路线只做“提前消除逆向绕行”的确定性规范化。两条轨迹
均为零差异，且已进入真实资源 `Verify.ps1` 的严格门禁。

这些证据仍只证明第一关两个移动片段，不能把 m000 或导航 domain 标成
完成。另一个重要取证结论是：原版
运行时活动对象数组下标并不等于 VWF `scene_index`，其中的角色数据库字段
也不能直接当作 DBL entry。当前只登记已经由位置、阵营和唯一性共同证明的
强子映射（VWF scene 1436 / DBL 924）；敌军身份在建立可靠映射表前不得
猜测写入基线。

本地复现命令：

```powershell
.\tools\Import-ModAssets.cmd
.\tools\Run-RuntimeProbe.ps1 `
  -GodotExecutable D:\Godot\Godot_v4.7.1-stable_win64_console.exe
```

结果位于 `LocalAssets/qa/runtime-probe/parity/`，包括两份 Remake 轨迹
以及各自的机器可读 JSON、可读 Markdown 比较报告。

## 9. 每次提交的固定交付

每次完善必须同时完成：

1. 更新源代码和证据状态；
2. 增加或更新自动回归；
3. 运行 `tools/Verify.cmd`；
4. 从稳定 MOD 资源重建 `LocalBuild/1937Remake`；
5. 执行 PCK 与最终 EXE 冒烟；
6. 更新 parity contract 和相关逐关验收记录；
7. 再提交并推送。

这样用户始终运行到本次修改对应的新程序，而不是旧试玩包。
