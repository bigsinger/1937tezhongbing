# 原版全局随机运行态基线

## 用途与边界

`game/data/original_crt_random_runtime_state.json` 固定稳定 MOD 十二关进入游戏后
约五秒的进程实测。它不是凭反编译猜测出来的参数表，而是把同一时刻的
MSVCRT `rand()` 调用流与原版活动角色内存快照关联起来，用于回答：

- 哪些角色按什么 runtime 顺序更新；
- 路线等待与静止等待何时共用计数器并重置；
- 哪些角色持续跟随 `+0x23C` 指向的编队/追击目标；
- 五点局部搜索按什么调用点和值顺序生成；
- 每次保存、读取后，全局随机序号与角色局部相位应恢复到哪里。

该基线只证明已捕获时间窗内的规则和状态，不代表十二关任意长时间、所有条件
分支已经逐帧等价。未取证的消费者仍必须在 parity contract 中保持
`partial`，不能由本文件外推为“已完成”。

## 安全取证方式

原版侧使用 `M1937_RNG_TRACE=1` 显式启用的测试钩子。正常启动不存在该变量，
钩子不会安装。取证期间：

- `crt_rand` 热路径只把序号、返回值、调用点 RVA、线程、ESI 和
  `GetTickCount()` 写入 524,288 条固定容量进程内环；
- 低优先级线程批量输出 JSONL，热路径不做磁盘 I/O；
- 探针只读目标游戏进程的角色表，并只向目标窗口发送必要消息；
- 不移动、锁定、裁剪或读取系统全局鼠标；
- 每关保存进入/退出两份角色 CSV、遥测 JSONL 与结果文件，各文件 SHA-256
  一并写入基线。

可重复采集命令如下。原始证据和隔离运行副本必须放在 `E:\1937` 下，不提交
到 Git：

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File `
  .\Patch\analysis\tools\Test-ModRegression.ps1 `
  -Levels (1..12) `
  -CrtRandomRuntimeOnly `
  -CrtRandomRuntimeMilliseconds 12500 `
  -OutputRoot E:\1937\rng-runtime-state

powershell -NoProfile -ExecutionPolicy Bypass -File `
  .\Remake\tools\Build-CrtRandomRuntimeStateBaseline.ps1 `
  -EvidenceRoots E:\1937\rng-runtime-state `
  -MinimumCompleteRounds 120

powershell -NoProfile -ExecutionPolicy Bypass -File `
  .\Remake\tools\Test-CrtRandomRuntimeStateBaseline.ps1
```

生成器会重新检查 EXE/content profile、连续 LCG、调用点目录、角色地址映射、
完整 60 Hz 轮次、状态转换定律和 48 份证据文件哈希。任何缺关、序号断裂、
未知调用点、角色身份冲突或规律违例都会失败。

## 已恢复的运行规律

### 共用路线/静止计数器

SDK 现固定下列 `RuntimeActorV1` 字段：

- `+0x0F0/+0x0F4/+0x0F8`：上一轮世界坐标；
- `+0x16C/+0x170`：共用计数器与上限；
- `+0x184`：路线更新是否活动；
- `+0x18C`：追击命令变体；
- `+0x23C`：持久编队/追击目标；
- `+0x29C`：type 56 追击延迟计数器。

`sub_456070` 在角色位置与上一轮相同时增加 `+0x16C`；`sub_4587E0` 在
`+0x184 == 1` 的路线更新中增加同一个字段。达到边界后两条路径都按
`rand()%160+40` 取得下一上限。Remake 因此只维护一个可存档计数器，不再
为“待机”和“路线”各造一套相互漂移的时钟。

### 持久追击/编队关系

`sub_45D330` 只在当前角色 `movement_path_state == 0` 时处理 `+0x23C`：

- 目标仍有效时，把其当前坐标重新作为目标；
- 复制目标的命令变体；
- 距离大于 128 且 `rand()%10 < 5` 时允许快速移动；
- type 56 使用 `+0x29C` 的专用延迟；
- 被前车/前队员暂时挡住时保留命令，不在每个 tick 重新规划整张地图。

十二关共固定 140 条实际追击关系。它们按原 runtime actor 顺序接入
`SquadUnit`，状态和目标身份进入局内存档。

### 五点局部搜索

`sub_45D060` 的一次完整搜索严格消费五次随机调用：

1. X 绝对偏移；
2. Y 绝对偏移；
3. X 符号；
4. Y 符号；
5. 下一等待上限。

58 组完整搜索均通过顺序和结果校验；Remake 只有在同一运行条件成立时才消费
这五次调用。

## 环境粒子与全局流

m002 与 m005 的高流量补采样共验证 505,308 条环境粒子调用：

- m002：255,195 条、560 次更新；
- m005：250,113 条、561 次更新；
- 两关只有 **80°** 风向能逐调用点完整消费全部记录，其他候选角度会在前
  7—16 次更新内发生调用点错位；
- 原版字段为 150 个主粒子与 20 个次粒子，重置、寿命、速度、尺寸、显隐
  相位和重生分支均按原调用顺序运行。

Remake 使用批量随机事务一次提交同一更新的调用，再由 `MultiMesh` 批量绘制；
这改变实现成本，不改变全局随机序号、返回值、粒子状态或可见结果。粒子状态
与全局 CRT state/draw index 在同一个存档事务中保存和恢复。独立性能门禁要求
600 次更新平均不超过 1 ms，当前参考机约 0.066 ms/次。

本地复核高流量证据：

```powershell
node .\Remake\tools\Analyze-AmbientParticleRuntime.mjs `
  --telemetry E:\1937\rng-runtime-state-heavy\level-03\crt-random-runtime-telemetry.jsonl `
  --width 1024 --height 768
```

## Remake 接线与验证

- `original_crt_random_runtime_state.gd` 只读加载并校验逐关证据；
- `main.gd` 按 60 Hz、runtime actor 优先级执行已恢复消费者；
- `squad_unit.gd` 接入共用计数、追击、局部搜索和稳定 MOD 路线时间线；
- `legacy_ambient_particle_field.gd` 恢复环境粒子并支持存读档；
- `GameSessionState` 保存全局流、角色相位、追击和粒子状态；
- `Test-CrtRandomRuntimeStateBaseline.ps1`、`original_crt_random_test.gd`、
  `save_settings_test.gd` 与 `ambient_particle_performance_test.gd` 共同进入
  `Verify.ps1`。

最密集的 m005 还使用按方向足印预热、运行证据路径缓存和压缩静态障碍掩码，
避免多格摩托车/推车为每次追击设置再恢复数千个 A* 格。该优化仍调用恢复的
原版反向均匀代价寻路，保留邻居顺序、同分插入规则和最终朝向。两次独立
24 秒窗口复测分别为 P95/P99 `19.018/22.251 ms` 与
`18.856/21.861 ms`，均低于 `20/25 ms` 门禁，且
`global_pointer_control=false`。

同一提交的完整 `Verify.ps1` 进一步跑过十二关 48 秒真实窗口短门禁：
2,160 帧整体 P95/P99 为 `17.924/20.196 ms`、最大 `33.383 ms`、
零个超过 50 ms 的帧；m005 为 `18.964/22.032 ms`。207 个自动输入事件
全部限制在目标视口，仍未控制系统鼠标。

## 仍未关闭的边界

- 首轮以后所有条件随机消费者尚未全部迁移；
- 攻击间隔仍保留已通过稳定 MOD 差分的过渡保护，防止部分迁移导致流错位；
- 各关仍需要更长的稳定 MOD/Remake 成对真人战斗、任务和媒体轨迹；
- 同 tick 多系统仲裁、特殊警报覆盖及部分导演时序仍需地址/录像证据；
- Windows 11、更多显卡与跨机器发布包仍需验收。

这些项目完成前，全局随机、AI、导演和 Windows 发布相关 parity domain
必须继续保留其真实的 `partial` 状态。
