# MOD 与 MapEditor 持续改进评估

> 实施状态（2026-07-27）：本文 P0—P2 建议已全部落地；逐项证据见
> [持续改进实施验收矩阵](持续改进实施验收矩阵.md)，架构、运行与复验
> 说明见
> [MOD与MapEditor持续改进实施报告](MOD与MapEditor持续改进实施报告.md)。
> 第五节“暂不建议投入”的反建议项继续保持排除。

## 1. 当前基线

### MOD 已具备

- Windows 10/11 稳定窗口和现代缩放输出；
- DirectDraw 到 Direct3D 9/OpenGL 的兼容转换；
- 原版鼠标、底栏、F1、M 小地图和热键保持；
- IME 屏蔽、60 Tick、VSync 和消息泵节流；
- 12 个原版关卡及 3 个扩展关选择；
- 难度、敌军听觉和警报传播配置；
- 已验证 EXE 的初版 M1937SDK；
- 扩展关运行时文件名重定向，不改写磁盘 EXE 和存档。

### MapEditor 已具备

- 原版/扩展 VWF 只读导入；
- 五层网格、1,470+ 对象和原版素材预览；
- 活物巡逻路线、A* 还原和运动预览；
- 简单对象/图层/任务编辑及 JSON 任务包导出；
- `redeploy` 和 `composite` 两类原版 VWF 生成工具；
- 出生安全、全图连通、真实任务 scene 和逐段 A* 校验；
- 三个扩展关的统一关卡包清单和确定性构建入口。

当前最重要的判断是：项目已经跨过“能跑、能看”的阶段，下一阶段不应继续
堆零散功能，而应优先补齐**原生写回、任务闭环、质量可视化和长期回归**。

## 2. MOD 改进路线

### P0：发布可靠性与确定性

| 改进项 | 当前问题 | 验收条件 | 风险/工作量 |
|---|---|---|---|
| 地址彻底 SDK 化 | `OriginalLevelProbe`、`GameFrameProbe` 和少数分辨率补丁仍复制裸 RVA | 地址从同一机器清单生成 C++/C# 常量；CI 检查重复裸地址 | 中 |
| 扩展关路由数据化 | 第 13—15 关仍在代理中使用条件分支 | 一张只读路由表描述选择器关卡、引擎任务、VWF 名称和文件要求；探针遍历验证 | 中 |
| 关卡端到端回归 | 现有探针主要证明载入和响应，不能证明通关 | 12+3 关至少覆盖开始、主要阶段、胜利、失败和存读档；不移动全局鼠标 | 大 |
| 性能基线 | 60 FPS 设置降低卡顿，但没有逐关长期 P95/P99 基线 | 对菜单、小/中/大地图各运行 10 分钟；记录帧时间、CPU、读取峰值和卡顿点 | 中 |
| 安全诊断与回滚 | 代理补丁失败时主要是静默跳过 | 生成本地诊断日志，记录 EXE 身份、签名失败和启用项；不含隐私/桌面截图 | 小 |

#### 建议立即执行的技术调整

1. 从 `SDK/address-catalog.json` 生成探针常量，删除 C# 中的第二份地址；
2. 把关卡 13—15 的重定向改成静态描述表；
3. 建立 `Test-ModRegression.ps1`，默认只操作隔离进程和游戏窗口；
4. 对 dinput 写补丁结果做结构化日志，失败时保持原版行为而不是半启用。

### P1：输入、显示与性能体验

| 改进项 | 推荐方向 | 不推荐方向 |
|---|---|---|
| 高分辨率 | 保留 1024×768 原版逻辑画布，改进整数/比例缩放、锐化和无边框窗口 | 再次扩大原版内部画布；它会破坏底栏、F1 和 M |
| 鼠标卷屏 | 对原版边缘卷屏做帧时间和输入延迟测量，只在窗口客户区判定边缘 | 全局锁鼠标、回中或主动 `SetCursorPos` |
| 偶发卡顿 | 区分资源首次加载、消息泵、Present 阻塞和磁盘读取，按来源修复 | 继续叠加多个限帧器或无证据调整线程优先级 |
| 菜单现代化 | 继续增强外部启动中心，原版菜单保持兼容兜底 | 在尚未恢复 UI 状态机前直接替换原版内部菜单 |
| 输入重映射 | 在代理层增加显式、可关闭的按键映射表，并保留 F1/M 原语义 | 提前吞掉所有键盘消息 |

### P1：敌军智能增强

当前已调整听觉与警报传播，但“更聪明”还不等于简单扩大半径。建议按可验证
的小步状态机实现：

1. **调查**：记录声源或最后目击位置；
2. **协同**：限定半径内通知少量队友，避免全图同步；
3. **搜索**：到达最后位置后检查 2—4 个可达邻近点；
4. **截击**：根据玩家最后方向选择前方路口，而不是直接知道实时坐标；
5. **脱离**：超时后分阶段返回巡逻，避免永久追击；
6. **难度约束**：反应时间、同时攻击者和搜索点数随 AI 等级变化。

验收时必须同时记录发现时间、增援数量、玩家脱离成功率和 CPU/A* 开销。
AI 不应读取视线外的玩家实时位置，也不能因为警报传播造成出生秒杀。

### P2：开放式插件能力

最大的长期限制是只有 12 套原版任务状态机。要支持真正新的任务类型，需要
在 SDK 上增加受版本保护的插件 ABI 或外部任务 sidecar：

- 世界事件转发：到达、击杀、拾取、爆破、交互、撤离；
- 任务图：依赖、计数、可选目标、成功和失败；
- 保存/读取：插件状态随原存档或独立 sidecar 原子保存；
- UI：目标列表、提示和失败原因；
- 版本：插件 API、EXE build 和任务 schema 明确协商。

这是高价值、高风险项目，应在 SDK 地址覆盖、事件语义和存档安全完成后再做，
不能直接在正式 Mod 中试验。

## 3. MapEditor 改进路线

### P0：原生 VWF 写回

当前编辑器可以读取 VWF、编辑内存模型并导出 JSON，但 GUI 不能把任意编辑
安全写回原版 VWF。优先目标：

- 只允许已知 VWF 版本；
- 原文件只读，另存为新 VWF；
- 临时文件写入、重新解析、结构校验后再原子替换；
- scene 数量、记录长度和巡逻容量不允许隐式变化；
- 所有坐标、参考坐标、路线和动态占用同步；
- 生成前后显示二进制与语义差异；
- 自动保留 `.bak`，失败不留下半写文件。

验收：m000—m014 做“导入→无修改另存”结构等价测试；三个扩展关从设计源
生成后哈希确定；损坏输入、越界对象和路线容量变化必须拒绝。

### P0：地图质量检查可视化

把目前文档中的人工门逐步变成编辑器中的“问题面板”：

- 区块接缝的 L1/L2/L3 不连续；
- 建筑、桥、门、墙和大型 sprite 跨区块切线；
- 对象 footprint 与移动障碍不一致；
- 孤立通行区、窄口和不可达任务点；
- 出生区敌军视线、听觉、攻击和警报热区；
- 巡逻路线相交密度和同一狭路的会车风险；
- 前景/人物排序异常；
- 任务 scene 与所选原版状态机不匹配。

问题应分为 Error、Warning、Info；点击问题直接定位地图坐标和对象。

### P0：关卡包向导

在 GUI 中封装现有 `mission-package.json`：

1. 选择 `redeploy` 或 `composite`；
2. 选择源地图和原版任务骨架；
3. 自动分配扩展关编号与文件名；
4. 选择玩家、敌军、目标、接头和出口 scene；
5. 设置安全/连通阈值；
6. 一键生成预览、VWF 和报告；
7. 展示确定性哈希，但只有人工确认后才能接受为基线；
8. 导出选择器条目和代理路由草案。

这样普通制作者不需要手写 JSON，同时高级用户仍可审查 Git diff。

### P1：编辑效率

- 完整 Undo/Redo 命令栈；
- 多选、框选、对齐、分布、复制和批量属性；
- 矩形/画笔/填充地形与障碍层；
- 可拖拽巡逻点、插入/删除点及容量提示；
- 对象搜索、按 scene/资源/阵营筛选；
- 图层锁定、透明度、独显和组合预设；
- 自动保存恢复与未保存修改提示；
- 大地图虚拟化和局部重绘，避免全画布刷新。

### P1：任务与 AI 设计

- 可视化任务依赖图和原版状态机映射；
- 目标阶段、失败条件和撤离条件检查；
- 敌军朝向、扇形视线及遮挡预览；
- 听觉、攻击和警报传播半径叠加；
- 按 AI 等级模拟发现/协同范围；
- 从出生点到目标的可达热图与最短路线；
- 巡逻和玩家路线的时间轴预览。

这些预览必须明确标记“原版恢复值”“Mod 配置值”或“编辑器估算”，避免把
近似模拟误写成引擎真实结果。

### P2：资产与协作

- 为每个素材补充 footprint、遮挡、门、层级和类别元数据；
- 支持跨地图区域素材库，但复制时重新绑定 scene 和占用；
- 语义化地图 diff：对象移动、路线变化、图层变化和任务变化；
- 冲突检测和可合并的 JSON 设计源；
- 插件式导入/导出器，为后续 SDK/sidecar 任务格式留接口；
- 一键生成 README 地图缩略图、故事章节和验证摘要。

## 4. 推荐实施顺序

### 里程碑 A：确定性工具链

- SDK 地址生成 C++/C# 双端常量；
- 扩展关路由数据化；
- 三个关卡包统一 CI 重建；
- 代理诊断日志。

退出条件：干净克隆可自动重建并验证所有扩展关，工具不再复制裸地址。

### 里程碑 B：编辑器可安全写回

- Undo/Redo；
- 原生 VWF 另存；
- 二进制/语义差异；
- 原子写入与备份；
- 问题面板第一版。

退出条件：不依赖命令行即可制作 `redeploy` 关卡，且错误编辑不能产出损坏
VWF。

### 里程碑 C：合成地图质量

- 接缝/footprint 检查；
- 连通热图；
- 视线、听觉、攻击和警报预览；
- composite 向导与局部预览；
- 大地图性能优化。

退出条件：新地图不再依赖截图后人工寻找明显断路和半栋建筑。

### 里程碑 D：玩法闭环

- 真实输入回放；
- 关卡阶段遥测；
- 胜利、失败、存读档回归；
- AI 搜索/协同小步增强；
- 经过证据支持后再评估 sidecar 任务插件。

退出条件：每个发布关有完整通关证据，不再只证明“进入关卡 40 秒未崩溃”。

## 5. 暂不建议投入的方向

- 恢复已停止的完整复刻工程；
- 用新 D3D 版本重写整个渲染器而没有明确性能瓶颈证据；
- 再次扩大原版内部逻辑分辨率；
- 全局操控、锁定或回中系统鼠标；
- 在没有存档兼容设计前加入复杂新任务状态机；
- 用大量随机敌人替代经过路线和补给调校的难度设计。

下一阶段最合理的第一批实施项是：**SDK 地址单一来源、关卡路由数据化、
MapEditor 原生 VWF 另存和质量问题面板**。它们同时降低后续 MOD、地图和
插件开发的返工风险。
