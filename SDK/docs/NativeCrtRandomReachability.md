# 原版 CRT 随机调用可达性收口

本文固定 `M1937.exe`（SHA-256
`F4DD1131DF6C993C01EA011F9439BC725E6DC6491B5FBBA47724D7D5B64DA3F3`）中
三个曾被误列为“正式关卡缺失”的 `rand()` 调用点。分析只使用 IDA 数据库、
可执行文件交叉引用和已有十二关进程内随机轨迹，没有启动游戏或进行人工通关。

## `0x0005BFAC`

`sub_45BD40` 在 `a2 == 0` 时用 `max(rand() % 9, 1)` 改写角色朝向。
它只有两个直接调用者：

- `sub_449FA0` 的 `0x0044A056`；
- `sub_44A090` 的 `0x0044A146`。

这两个调用者在受支持 EXE 中都没有任何入站代码引用、数据引用或 PE 入口点；
十二关启动、首轮和后续完整更新轨迹中也没有 `0x0005BFAC`。正式关卡使用的是
可达的 `sub_45B950` 载入路径（`0x0005BBBC`），后者已经接入动态角色工厂。
因此 `sub_45BD40` 是保留在二进制中的未引用重载 API，而不是存档恢复或正式
关卡运行时消费者。

## `0x00061DFC` 与 `0x00061E3A`

`sub_461D10` 从关系匹配的 SPR 候选中执行 `rand() % count`；当两侧关系相等时，
再用 `rand() % 4` 选择方向。调用链只属于地图制作时的地形填充与边缘自动拼接：

```text
0x0044ACA0 terrain-fill thunk -> sub_460E60 -> sub_461D10
0x0044ACC0 autotile thunk     -> sub_462B40 -> sub_462070 -> sub_461D10
```

两个入口 thunk 均无入站代码引用、数据引用或 PE 入口点，十二关进程内随机轨迹
也从未出现这两个调用点。正式游戏直接读取 VWF 中已经写好的地形关系，不在运行
时重新随机拼接地图。因此它们属于未使用的地图创作 API，不应要求 Remake 在关卡
载入或绘制时额外消费随机数。

## 契约结论

`SDK/crt-rand-call-sites.json` 仍完整保留全部 119 个直接调用点，但以上三个点的
`formal_missions` 设为 `false`。正式十二关因此共有 107 个可达调用点：106 个由
实时共享随机流消费，1 个由精确启动检查点恢复，缺失数为 0。两个角色析构重置
调用者仍以 `partial_runtime` 单独跟踪，直到所有可达动态删除生命周期均有证据。
